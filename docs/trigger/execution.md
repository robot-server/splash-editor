# [트리거/로직 패턴]

## 실행 순서에 의존하는 액션 연결

- 패턴 이름: 동일 플레이어 트리거의 순차 상태 처리
- 구현하고자 하는 기능: 생성·소비·이동·승패 액션 사이의 선후관계를 명시한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 스에아 [트리거 작동 원리](https://cafe.naver.com/edac/book5095361/76436)는 같은 플레이어 트리거와 액션의 위→아래 처리 순서를 예제로 설명한다. 필요한 순서를 트리거 목록에서 위쪽/아래쪽 배치와 액션 배열에 반영한다. 여러 플레이어 소유자에 같은 트리거를 체크하면 플레이어별 복제처럼 동작할 수 있으므로 `Current Player` 기준과 대상을 함께 설계한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 순서 의존성이 존재하면 앞 트리거가 생성한 유닛을 다음 트리거가 즉시 세거나 제거하는지 작은 게임 시나리오로 확인한다. 같은 플레이어의 여러 반복 트리거에 `Wait`를 섞으면 강좌 예시처럼 한 Wait가 다른 흐름을 지연시킬 수 있다. 서로 독립된 시간 흐름은 countdown/death-count 상태 등 별도 수단을 검토하고 실제 타이밍을 잰다.

## 반복과 종료

일회 실행인지 반복 실행인지 의도를 정하고, 반복이면 `Preserve Trigger`와 상태 소비/재설정을 짝짓는다. 웨이브 완료·최종 승리·새 웨이브 시작의 조건이 동시에 참이 될 때 순서가 결과를 바꾸지 않는지 검증한다. Hyper Trigger나 Fastest 속도에 따른 실행 주기를 수치로 가정하지 않는다. 선택한 맵·게임 버전에서 실제 시간과 동작을 확인한다.
