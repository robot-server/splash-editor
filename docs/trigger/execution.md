# 트리거는 어떻게 도는가

출처: 스타 에디터 아카데미 [초급4] 트리거의 작동 원리
(`cafe.naver.com/edac/book5095361/76436`), [초급5] 트리거의 중요 기능들
(`…/76451`).

## 순서가 있다 — "동시" 는 없다

트리거는 한 프레임 안에 다 처리되지만 **엄연한 순서가 있다.**

```
플레이어1의 트리거들 → 플레이어2 → … → 플레이어8
같은 플레이어 안에서는 위에서 아래
한 트리거 안의 액션도 위에서 아래
```

그래서 같은 프레임에 도는 두 트리거라도 **순서가 결과를 바꾼다.**

| 순서 | 결과 |
| --- | --- |
| 히드라 생성 → 히드라 킬 | 생성되자마자 죽는다 |
| 히드라 킬 → 히드라 생성 | 있던 것을 죽이고 새로 생긴다 |

## 여러 플레이어에 체크한 트리거 = 플레이어마다 따로

플레이어 1·2·3 에 체크한 트리거는 **한 덩어리가 아니다.** 플레이어별로
같은 트리거를 하나씩 만든 것과 같다. `Force N` 체크는 그 세력의 모든
플레이어에 체크한 것과 같다.

이것이 `"Current Player"` 가 뜻이 있는 까닭이고, `Display Text Message`
가 **그 트리거를 실행하는 플레이어에게만** 보이는 까닭이다.

## 웨잇 꼬임 — 플레이어당 웨잇은 하나뿐

**`Wait` 는 플레이어마다 한 번에 하나만 돈다.** 두 개 이상이 걸리면
하나만 진행되고 나머지는 그게 끝날 때까지 기다린다.

카페의 예:

```
트리거 A: Always → 저글링 생성, Wait(5000), Preserve
트리거 B: Always → 질럿 생성,  Wait(7000), Preserve
```

기대: 저글링 5초마다, 질럿 7초마다.
실제:

```
저글링·질럿 ─5초─ 저글링 ─7초─ 질럿·저글링 ─5초─ 저글링 ─7초─ …
```

A 의 5초 웨잇이 도는 동안 B 의 7초 웨잇은 **시작도 못 한다.**

> **한 플레이어에 웨잇을 쓰는 트리거를 둘 이상 두지 않는다.** 주기가
> 필요하면 `Countdown Timer` 나 죽음 수 카운터를 쓴다.

## 하이퍼(터보) 트리거

기본 주기는 실제 **1.26초**다. `Wait(0)` 63개 + `Preserve Trigger` 로
이루어진 트리거를 **3~4벌** 두면 주기가 프레임 단위로 줄어든다.

지켜야 하는 것 둘:

1. **게임 안에 항상 있는 플레이어**여야 한다 — 컴퓨터 슬롯을 쓴다.
   "열림" 으로 두면 아무도 안 앉았을 때 안 돈다.
2. **하이퍼를 건 플레이어는 웨잇을 쓰면 안 된다.** 웨잇이 돌 때마다
   하이퍼가 멈춘다 (위의 웨잇 꼬임).

내가 틀렸던 것: 하이퍼를 `"All players"` 에 걸었다. 사람 플레이어에
걸면 그 사람의 다른 웨잇 트리거가 전부 먹통이 된다.

## Preserve Trigger

없으면 트리거는 **한 번 실행되고 사라진다.** 있으면 계속 남는다.

하이퍼와 같이 쓰면 조건이 참인 동안 **매 프레임** 돈다. 그래서
잠금이 없는 보상 트리거는 1초에 스물네 번 돈다 —
[recipes.md](recipes.md) 의 "누적 조건으로 보상을 주지 않는다" 참고.

## 요약

| 지킬 것 | 안 지키면 |
| --- | --- |
| 액션 순서를 뜻대로 놓는다 | 생성하자마자 죽이거나 그 반대가 된다 |
| 한 플레이어에 웨잇 트리거는 하나 | 웨잇 꼬임으로 주기가 엉킨다 |
| 하이퍼는 컴퓨터 플레이어에, 3~4벌 | 안 돌거나 사람의 웨잇을 먹는다 |
| 하이퍼 플레이어에는 웨잇 금지 | 하이퍼가 멈춘다 |
| `Preserve` 를 붙였으면 잠금을 둔다 | 매 프레임 돈다 |
