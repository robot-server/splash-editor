# [트리거/로직 패턴]

## Switch Randomize 결과를 비트로 조합

- 패턴 이름: 독립 switch 상태를 death count 비트에 누적
- 구현하고자 하는 기능: 단일 트리거 시스템에서 여러 결과 중 하나를 고른다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Set Switch(Switch n, randomize)` → 각 스위치가 Set인 경우 서로 다른 `Set Deaths(Add, bit weight)` → 조합된 값을 `Deaths(Exactly 또는 범위)`로 분기 → 선택 결과 액션 → 다음 시행을 위해 결과 death count를 초기화한다. [스에아 랜덤 구현 강좌](https://cafe.naver.com/edac/book5095361/76590)는 switch Set/Cleared 상태를 이진수 자리로 보고 조합하는 방법을 보여 준다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): N개 결과보다 넓은 이진수 범위를 만들면 범위 밖 값 처리 정책이 필요하다. 강좌의 기본 방법은 범위 밖 결과를 다시 시행하는 흐름이다. 재시행 빈도·지연이 허용되지 않는 기능은 결과 범위와 재시도 조건을 별도 설계하고 무한 대기/상태 누적을 막는다. 반복 시행 전 누적 death count를 초기화한다. 스위치와 death count를 다른 시스템에서 공유하지 않는다.

## 누적 상태로 범위를 순환

- 패턴 이름: 난수 증가분과 모듈로 보정으로 선택값 갱신
- 구현하고자 하는 기능: 매 시행마다 범위 밖 결과를 버리고 재시도하지 않고 현재 값을 계속 갱신한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 현재 상태에 무작위 증가분을 더하고, 결과가 선택 범위 이상이면 범위 크기를 빼는 보정 트리거를 적용한다. 증가분의 최대치에 따라 한 회에 보정이 한 번으로 충분한지, 두 번 이상 필요한지 계산한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): `Add` 값 범위와 보정 조건/횟수가 상태를 의도된 유효 범위로 되돌리는지 최댓값으로 시험한다. “균등 분포”는 트리거 이름만으로 보장되지 않으므로 선택별 분포를 여러 시행으로 검증한다. 여러 트리거를 쓸 경우 플레이어별 트리거 실행 순서를 확인한다.

# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 해당 없음. 결과가 유닛 배치로 이어질 때 각 결과 생성 위치의 지형/건설 공간을 따로 확인한다.
- 유닛 길막/동선 보장 규칙: 랜덤 결과가 유닛·건물 생성이면 각 분기 위치가 생성할 유닛에 유효한지 확인한다. 비어 있지 않은 위치의 생성 실패 행동은 게임에서 직접 시험한다.
