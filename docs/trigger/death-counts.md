# [트리거/로직 패턴]

## 데스값을 맵 상태 변수로 사용

- 패턴 이름: 유닛별 death count 필드를 식별 가능한 시나리오 변수로 사용
- 구현하고자 하는 기능: 단계, 레벨, 목숨, 선택 결과, 누적 점수 등 플레이어별 수치를 유지한다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Deaths(상태 소유자, 예약 유닛 타입, comparison, 값)`으로 상태를 읽고, `Set Deaths(상태 소유자, 같은 유닛 타입, Set To/Add/Subtract, 값)`으로 갱신한다. 초기값을 분명히 정하고 상태를 읽는 트리거와 갱신 트리거를 해당 기능의 플레이어 소유자에 둔다. [스에아 데스 트리거 강좌](https://cafe.naver.com/edac/book5095361/76491)는 실제 유닛 사망 외에도 Set Deaths로 값을 설정해 활용하는 방식을 설명한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 예약 유닛 타입이 맵에서 실제로 생성/사망하거나 자동 생성되는 용도로 쓰이지 않도록 전체 유닛 출처를 확인한다. 수치 필드의 플레이어별 범위를 확인하고, 멀티플레이어라면 플레이어 간 상태 간섭 여부를 검증한다. 실제 처치 수를 소비해 보상할 때는 변수를 보관하는 패턴과 혼동하지 않는다. 성공 보상 후 `Subtract`로 처리한 수를 소비하면 조건이 유지되어 보상이 중복되지 않게 할 수 있지만, 수량/액션 체인은 맵 상황에 맞게 시험한다.

## 여러 상태를 한 값에 비트 인코딩

- 패턴 이름: 동시 이벤트를 가중치가 겹치지 않는 비트로 누적
- 구현하고자 하는 기능: 서로 다른 이벤트가 같은 프레임에 들어와도 하나의 death count 값에서 출처를 구별한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 이벤트마다 다른 2의 거듭제곱을 `Add`하고, 판독 트리거는 큰 bit부터 `At least`로 검사한 다음 그 값을 `Subtract`해 소비한다. 예: 이벤트에 1/2/4/8을 더하고 값이 8 이상이면 8을 소비한 뒤 4, 2, 1을 검사한다. 기초 설명은 [스에아 동시작용 강좌](https://cafe.naver.com/edac/book1867614/20271)에 있다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 작은 비트부터 빼면 큰 이벤트 값이 먼저 소비될 수 있으므로 큰 자리부터 처리한다. 검사와 소비가 여러 트리거로 나뉘면 같은 플레이어의 위→아래 실행 순서에 의존하는지 확인하고, 아직 읽지 않은 비트가 지워지지 않는지 동시 입력으로 검증한다. 실제 유닛의 death count를 변수로 쓸 경우 자동 사망/생성으로 값이 변하지 않는지 테스트한다.

# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 상태 변수 패턴 자체는 지형에 제약이 없다. Bring 기반 상태 전이를 같이 쓸 때만 지정 로케이션의 접근성을 확인한다.
- 유닛 길막/동선 보장 규칙: 위치 상호작용을 상태 변경 조건으로 쓴다면 트리거가 참조하는 대상이 실제로 로케이션에 들어갈 수 있는지 검증한다. Deaths 저장용 유닛을 실제 플레이 오브젝트로 배치할 필요는 없다.
