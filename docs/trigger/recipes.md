# 상호작용 기능 조립 사례

## [트리거/로직 패턴]

- 패턴 이름: 선택 유닛·자원·상태 토큰을 함께 검사하는 구매
- 구현하고자 하는 기능: 플레이어가 구매 영역에 선택 유닛을 가져오고, 충분한 자원과 유효한 구매 상태가 있을 때 보상 유닛으로 교환한다.
- 조건(Condition) 및 액션(Action) 구조 체인: scmscx [원본 구매 맵](https://scmscx.com/map/2BqjYVjT)의 성공 체인은 `Bring(Current Player, 선택 유닛, 위치 03, At least, 1)` + `Accumulate(Current Player, At least, 비용, ore)` + `Deaths(Player 7, Terran Beacon, At least, 선택 번호)`로 승인한다. 액션은 선택 토큰 제거 → 영웅 생성 → 자원 차감 → 성공 문구·효과음 → `Preserve Trigger` 순서로 이어진다. 인자 배열은 [트리거 API](api.md)와 대조한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 원본에서 확인한 것은 성공 경로다. 잔액 부족 메시지, 보상 생성 실패, 생성 공간 부족 시 환불, 동시 구매 잠금은 이 체인에서 확인되지 않았다. 새 기능은 자원/토큰 소비 전에 상태·공간·생성 수량을 검사하고, 실패 시 상태를 유지하거나 환불하는 경로를 별도 구현한다. `Preserve Trigger`를 쓸 때 토큰 제거 또는 상태 전이로 반복 성공이 의도된 것인지 확인한다.

## [트리거/로직 패턴]

- 패턴 이름: 순간 메시지와 다시 열 수 있는 목표 설명 분리
- 구현하고자 하는 기능: 결과를 즉시 알리면서 가격·조작·비콘 효과를 플레이 중에도 참조하게 한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 기능 조건 → 실제 상태 변화 → `Display Text Message(Always Display, 결과)` 및 필요 시 `Play WAV`를 같은 결과 흐름에 둔다. 임무·조작·상호작용 규칙은 `Set Mission Objectives`에 별도로 기록하고, 시작 브리핑은 순차 안내로 구성한다. [액션 강좌](https://cafe.naver.com/edac/book5095361/76412)와 [미션 브리핑 강좌](https://cafe.naver.com/edac/book5095361/76453)는 각각 일반 트리거 액션과 조건 없는 브리핑 액션을 설명한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): `Always Display`는 자막 설정과 관계없이 메시지를 출력하는 옵션이지 영구 HUD가 아니다. 플레이 중 반복 참조가 필요하면 `Mission Objectives` 등 다시 열 수 있는 수단을 제공한다. 반복 메시지는 상태 전이·토큰 소비·재진입 조건으로 중복을 제어한다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 구매 로케이션·보상 생성 위치·보상 이동 목적지를 시각 표식과 맞춘다. 로케이션 판정은 지형 연결을 만들지 않으므로 접근할 보행 공간을 별도로 둔다.
- 유닛 길막/동선 보장 규칙: 구매 영역에서 보상 생성 위치까지 유닛 footprint와 기존 점유물을 검사하고, 생성 뒤 목표까지 이동할 길을 확보한다. Beacon·Powerup 계열의 강제 생성 예외를 일반 전투 유닛에 적용하지 않는다([생성 제약](../usemap/functional-design.md)).
