# 플레이어 실행 순서와 공유 상태

## [트리거/로직 패턴]

- 패턴 이름: 플레이어별 이동 로케이션을 하나의 임시 로케이션으로 순회
- 구현하고자 하는 기능: 플레이어가 조종하는 영웅마다 위치를 검사하되 플레이어별 이동 로케이션 복사본을 줄인다.
- 조건(Condition) 및 액션(Action) 구조 체인: 스에아 [Trigger의 발동 순서](https://cafe.naver.com/edac/book1867614/20272) 예시는 각 플레이어 소유 트리거에서 `Bring(해당 플레이어, 영웅, 조건)`을 확인하고 `Move Location(공유 로케이션, 해당 플레이어의 영웅)`을 실행한다. 플레이어 트리거는 P1에서 P8 순으로, 같은 플레이어 안에서는 위에서 아래로 처리되므로 공유 로케이션을 다음 플레이어 영웅으로 덮어쓴 뒤 그 플레이어의 조건 트리거가 읽게 구성한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 이동 로케이션 트리거를 그 플레이어의 조건 트리거보다 위에 둔다. 같은 플레이어가 영웅을 여러 개 조종할 수 있으면 공유 로케이션이 덮어써지므로 이 방식을 그대로 적용하지 않는다. 사람 턴 뒤에 실행되는 컴퓨터 소유 액션은 마지막 사람 위치를 읽을 수 있다. 강좌는 리콜 효과가 잘못된 사람에게 적용될 수 있는 이 사례를 들어 별도 로케이션 또는 플레이어별 컴퓨터 제어를 권한다. 이 절약 방식은 성공 기능과 부작용을 함께 검토한 뒤 쓴다.

## [트리거/로직 패턴]

- 패턴 이름: 같은 실행 주기 안의 자원 증감 순서 제어
- 구현하고자 하는 기능: 자원값을 화면에 바꾸지 않고 내부 계산에 사용하거나, 0 자원에서 누적값을 한쪽으로만 남긴다.
- 조건(Condition) 및 액션(Action) 구조 체인: 강좌의 예시는 같은 플레이어 소유 `Always -> Set Resources(Add, 1 ore) -> Preserve Trigger` 뒤에 `Always -> Set Resources(Subtract, 1 ore) -> Preserve Trigger`를 두면 한 루프에서 증가분이 상쇄된다고 설명한다. 반대로 차감 액션을 먼저 두면 자원이 0일 때 차감은 적용되지 않고 뒤의 증가분이 남는다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 조건이 같은 트리거끼리는 위아래 순서가 상태 결과를 바꾸므로 목록 순서를 명시적으로 배치한다. 이 강좌 사례는 자원 액션 순서에 대한 설명이며, 다른 액션이나 다른 플레이어에서도 동일 결과가 난다고 일반화하지 않는다. 루프마다 상태를 바꾸는 트리거 수와 게임 내 자원 표시를 직접 확인한다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 이 강좌는 지형 편집 규칙을 다루지 않는다.
- 유닛 길막/동선 보장 규칙: 공유 로케이션은 트리거 순서대로 한 영웅 위치를 가리키므로, 동시에 여러 유닛의 위치를 유지하는 저장 공간처럼 쓰지 않는다.
