# 트리거 수를 줄이는 법 — **n×m 을 n+m 으로**

출처: 스타 에디터 아카데미 `에디터의 모/든/것`
[조립식 트리거: 경우의 수 최소화](https://cafe.naver.com/edac/book1678930/19989) ·
[Trigger의 발동 순서](https://cafe.naver.com/edac/book1867614/20273).

실측 유즈맵의 트리거 중앙값이 **193개**, 90% 지점이 **761개**다
([../chk/anatomy.md](../chk/anatomy.md)). 손으로 다 쓰면 실수가 난다.
**경우의 수를 곱하지 말고 더한다.**

## 곱하는 구조 — 흔한 실수

"플레이어 3명 × 고를 유닛 3가지" 를 그대로 쓰면 트리거가 **9개**다.

```
P1 이 다크아콘 골랐으면 → P1 자리에 다크아콘
P1 이 아콘 골랐으면     → P1 자리에 아콘
P1 이 럴커 골랐으면     → P1 자리에 럴커
P2 가 다크아콘 …        (아홉 벌)
```

**6명 × 10가지면 60개**다. 하나만 잘못 써도 찾기 어렵다.

```
n명 × m가지 = n·m 개
```

## 더하는 구조 — 두 단계로 나눈다

`f`(유닛을 만든다)와 `g`(제 자리로 옮긴다)를 **합성**한다.

```
1단계 (m개)   무엇을 골랐나  →  임시 자리에 그 유닛을 만든다
2단계 (n개)   임시 자리의 유닛 →  고른 사람의 자리로 옮긴다
```

```
n명 + m가지 = n + m 개
```

6명 × 10가지가 **60 → 16** 이 된다.

### 왜 되는가 — 트리거 차례

트리거는 **P1 → P8**, 한 플레이어 안에서는 **위 → 아래**로 돈다.
1단계를 위에, 2단계를 아래에 두면 **같은 주기 안에** 만들고 옮기는
일이 끝난다. 임시 자리에 유닛이 남을 틈이 없다.

→ [execution.md](execution.md)

## 같은 얼개가 쓰이는 곳

| 자리 | 1단계 | 2단계 |
| --- | --- | --- |
| 상점 | 무엇을 샀나 | 산 사람에게 준다 |
| 스킬 | 어떤 스킬인가 | 쓴 사람 자리에 효과 |
| 부활 | 누가 죽었나 | 그 사람 자리에 되살린다 |

`Current Player` 를 쓰면 2단계가 **한 벌로 줄기도 한다** — 트리거
소유 플레이어가 곧 그 사람이기 때문이다
([conditions.md](conditions.md) 의 Player 인자).

## 로케이션도 아낀다

영웅마다 `Move Location` 을 따로 둘 까닭이 없다. 로케이션 하나를
차례로 옮겨 쓰면 된다 — 트리거가 위에서 아래로 도니까.

**한 플레이어가 영웅을 둘 이상 조종하면** 이야기가 다르다. 그때는
따로 둔다.

로케이션은 이름이 곧 스트링이고 **스트링은 1024개 제한**이라
아끼는 값이 있다 ([briefing-strings.md](briefing-strings.md)).
