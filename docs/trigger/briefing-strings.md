## 미션 브리핑

유즈맵을 열면 게임 **전에** 뜨는 장면이다. 실측 유즈맵 127장 중
**85%가 쓰고, 중앙 2트리거**다 ([chk/sections.md](../chk/sections.md)).

### 트리거와 다른 점

- **조건이 없다.** 플레이어와 액션만 있다. 적힌 차례대로 흐르는
  일직선 진행이다.
- **스위치 개념이 없다.** 스위치 버튼이 먹지 않는다.
- 액션 실행 순서는 트리거와 같다 — 위에서 아래.
- 액션 칸이 **64개** 제한이지만, 차면 브리핑 트리거를 하나 더 만들면 된다.

### 액션

| 액션 | 하는 일 |
| --- | --- |
| `Show Portrait` | 슬롯에 얼굴을 띄운다 (유닛, 슬롯 번호) |
| `Display Speaking Portrait` | 그 슬롯 얼굴을 N 밀리초 동안 **말하게** 한다 |
| `Hide Portrait` | 얼굴을 숨긴다 |
| `Text Message` | 가운데에 글을 띄운다 (글, 밀리초) |
| `Mission Objectives` | 왼쪽 임무 목표 칸에 적는다 |
| `Wait` | 다음 액션까지 기다린다 |
| `Play WAV` | 소리 |

실측에서 쓰는 비율 (브리핑을 쓰는 맵 기준): `Mission Objectives` 83%,
`Text Message` 78%, `Wait` 65%, `Show Portrait` 55%, `Play WAV` 24%.

### 색 코드가 다르다

> 미션 브리핑에 적용되는 **색 코드는 `Display Text Message` 액션이나
> 유닛 이름 등에 쓰이는 색 코드와 다릅니다.** 유닛 이름에서 `<03>` 이
> 노란색이라면 미션 브리핑에서는 다른 색으로 나타납니다.

브리핑용 색은 텍스트 프리뷰어2 의 **Out-game** 탭에서 본다.
인게임 색 코드를 브리핑에 그대로 쓰면 엉뚱한 색이 나온다.

### 잘 쓰는 법

**한 트리거에 몰아넣지 않는다.** 실측 중앙이 2트리거인 것은 장면을
나눠 흐르게 한다는 뜻이다.

```
1번 트리거: Show Portrait → Text Message("…") → Wait
2번 트리거: Text Message("…") → Wait → Mission Objectives("…")
```

> 내가 틀렸던 것: 한 트리거에 모든 줄을 넣고 맵 설명에는 상점 가격까지
> 적었다. 실측은 반대다 — **브리핑이 길고 설명이 짧다**
> (설명 중앙 72바이트).

## 스트링 — 제한이 있다

맵 이름, 설명, 유닛 이름, 로케이션 이름, 트리거의 모든 글, 세력 이름,
**트리거 주석까지** 전부 스트링이다.

| 제한 | 값 |
| --- | --- |
| 스트링 종류 | **1024개** |
| 전체 용량 | 정해져 있다 (SCMDraft2 가 % 로 보여 준다) |

- **같은 글자는 한 개로 센다.** 마린 이름과 파이어뱃 이름을 둘 다
  `aaa` 로 하면 하나다.
- 그래서 **쓸데없는 스트링(트리거 주석 등)을 아껴야 한다.**
- 다만 SCMDraft2 에서 **같은 스트링을 여러 곳에 돌려쓰는 것은 권장하지
  않는다.** 나중에 지우거나 고칠 때
  `String corruption detected in line XXX` 오류가 난다.

`STRx` 를 쓰면 오프셋이 4바이트라 더 큰 용량을 쓸 수 있다 — 한글 맵에
많다 ([chk/sections.md](../chk/sections.md)).
