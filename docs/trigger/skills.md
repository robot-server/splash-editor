# 데스값 타이머를 이용한 반복 스킬

## [트리거/로직 패턴]

- 패턴 이름: 병렬 스킬 연출을 Wait 대신 플레이어별 Deaths 타이머로 구동
- 구현하고자 하는 기능: 캐릭터 주변 또는 지정 대상 위치에 연출 유닛을 순서대로 생성·제거하고, 스킬 중복 사용을 막는다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Always` → `Move Location(player, Current Player의 영웅, Anywhere)` → `Move Location(target, Force 2 유닛, player)` → 타이머마다 독립된 감소 트리거(`Deaths(Current Player, timer, At least, 1)` → `Set Deaths(..., Subtract, 1)`)로 캐릭터와 대상을 추적하고 활성 타이머를 감소시킨다. 생산 요청은 `Bring(Current Player, 요청 토큰, skill, At least, 1)` + 다른 스킬 타이머가 0인 조건 + 사용 잠금 해제 조건으로 승인하고, 요청 토큰을 소비한 뒤 해당 타이머를 양의 값 N으로 설정한다. 타이머 값 N에 도달하는 `Deaths` 조건이 연출 유닛 생성, 이후 N−3에서 제거, N−4에서 다음 생성 같은 순차 액션을 구동한다. 모든 타이머가 0이면 사용 잠금을 해제한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 0인 타이머를 감소시키면 0에 머문다고 가정할 수 없으므로 각 감소 트리거를 분리하고 해당 타이머가 1 이상일 때만 실행한다. 하나의 트리거에 여러 타이머의 `At least 1` 조건을 묶으면 어떤 타이머가 0일 때 트리거 전체가 멈춰 다른 타이머도 감소하지 않는다. `Switch`는 맵 전체 공유 상태이므로 이를 사용하면 전역 잠금이 된다. 플레이어별 병행 사용을 원하면 잠금도 플레이어별 Deaths 상태 등으로 분리한다. 승인·감소·연출 트리거의 실행 순서를 정하고, 타이머 설정 직후 N 단계가 건너뛰지 않는지 확인한다. `Wait` 흐름은 같은 소유자의 다른 `Wait` 트리거와 지연을 공유할 수 있다. 스킬 사용 중 새 토큰을 처리할 분기를 두고, 생성 위치의 점유·생성 실패·대상 부재 뒤 타이머와 잠금이 정리되는지 검증한다.

## [지형/배치 메커니즘]

- 메커니즘 이름: 캐릭터 추적 로케이션과 대상 추적 로케이션 분리
- 적용 이유/목적: 아군 캐릭터 위 생성과 적 유닛 위 생성의 좌표가 섞이지 않도록 한다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 캐릭터 추적 `player`, 적 추적 `target`, 토큰을 받는 `skill`, 연출 유닛을 배치할 `skill` 또는 전용 위치를 별도 구성한다. 역할이 다른 로케이션은 이름과 영역을 분리한다. 로케이션 하나는 현재 좌표 하나만 담으므로 복수 대상을 별도로 추적할 필요가 있으면 선택·순회 상태를 추가한다.
- 잘된 예시 및 실패하는 나쁜 예시: 생성 목적에 맞는 캐릭터/대상을 추적하고 그 지점에 연출 유닛이 나타나면 성공이다. 대상이 없는데 이전 좌표를 유효한 표적으로 쓰거나, 적 추적 로케이션을 여러 대상이 덮어써 아군 위에 공격 연출이 생성되면 실패다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 생성 위치가 높은/낮은 지형 중 어디를 따르는지 위치 필터를 대상 이동과 함께 확인한다. 이동형 연출 유닛은 지형과 통로에 막힐 수 있으므로 생성 위치와 이동 명령을 나눠 검증한다.
- 유닛 길막/동선 보장 규칙: 각 생성 이벤트의 위치 footprint, 기존 유닛 점유, 동시 생성량, 제거 타이밍, 대상까지 이동 경로를 확인한다. 생성 실패 뒤 비용·토큰·사용 상태의 복구 경로를 재현하고, 모든 플레이어에서 동시에 한 개만 실행되는지 또는 병렬 실행되는지 명시한다.
