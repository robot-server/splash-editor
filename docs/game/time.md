# [트리거/로직 패턴]

## 게임 시간 조건을 실제 대기 시간으로 맞추기

- 패턴 이름: Countdown Timer·Elapsed Time·Wait의 시간 단위 구분
- 구현하고자 하는 기능: 제한 시간, 버프 지속 시간, 유닛 생산·연구 시간과 트리거 대기를 원하는 실제 시간에 맞춘다.
- 조건(Condition) 및 액션(Action) 구조 체인: 실제 제한 시간 `t`초를 Countdown Timer 또는 Elapsed Time에 넣을 때 `round(t / 0.672)`를 사용한다. Fastest에서 두 조건의 1단위는 실제 약 0.672초다. 생산시간 설정의 1단위는 약 0.042초이며, 연구·업그레이드 시간은 SCMDraft 설정에서 Normal 기준 초를 사용하므로 Fastest 실제 시간은 설정값에 약 0.63을 곱해 계획한다. Wait는 밀리초 값을 프레임 간격으로 올림한 뒤, 끝난 다음 프레임에 트리거가 재개된다.
- 예외 처리/버그 방지 로직: Wait 1000ms는 24프레임 대기 후 다음 프레임에 재개되어 약 1.05초 뒤 동작한다. Wait를 정확한 초 단위 타이머처럼 쓰지 않는다. Hyper Trigger가 없으면 Preserve Trigger 주기가 약 30프레임(1.26초)이므로 타이머 조건이 참이어도 그 실행 주기만큼 판정이 늦을 수 있다. Hyper Trigger를 추가하면 트리거 실행 속도와 공유 상태/Wait 상호작용도 함께 확인한다.

## 변환 예시

Countdown Timer와 Elapsed Time에 넣을 값은 Fastest 기준 다음과 같다.

| 원하는 실제 시간 | 조건 값 |
| --- | ---: |
| 5초 | 7 |
| 10초 | 15 |
| 12초 | 18 |
| 30초 | 45 |
| 1분 | 89 |
| 3분 | 268 |

Wait의 프레임 양자화는 초 단위 제한 시간과 별개다. 1000ms 입력은 실제 대기 1.008초에 재개 프레임을 더해 약 1.05초 뒤 트리거가 실행된다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 시간 문턱을 통과해야 하는 이동 구간은 목표 플레이 속도에서 유닛 이동과 트리거 판정 지연을 함께 측정한다. 게임 시간 조건 값만으로 이동 시간을 보증하지 않는다.
- 유닛 길막/동선 보장 규칙: 이동 목표까지의 실제 경로와 생성·충돌 지점을 게임에서 확인한다. 유닛별 타일/초 값을 이 문서의 시간 환산만으로 추정하지 않는다.

## 출처와 범위

시간 단위와 Wait 재개 시점은 [시간·프레임 강좌](https://cafe.naver.com/edac/book5095361/76812), 지속시간 예시는 [타이머 지속시간 강좌](https://cafe.naver.com/edac/book5095361/77409)에 근거한다. 트리거 사이클은 강좌 설명의 실행 조건이며, 다른 게임 버전·속도 설정에서는 목표 버전에서 재현한다. 이동 속도 환산은 이 자료가 제공하지 않으므로 여기서 일반화하지 않는다.
