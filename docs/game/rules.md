# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: Height Transition, Pathfinder Regions, 시야 고저, 공격 사거리, 이동 연결은 서로 다른 판정이다. 오버레이 표시 하나로 실제 게임 이동·공격을 추정하지 말고 대상 게임 버전에서 재현한다.
- 유닛 길막/동선 보장 규칙: 슬롯·종족·Start Location·배치 유닛 관계, 건물/유닛 충돌과 생성 공간, 트리거 액션 순서를 하나의 플레이 시나리오에서 확인한다. 게임 버전이나 로비 설정이 달라지면 같은 CHK라도 결과를 다시 검증한다.

## 대상 버전에서 런타임 조건 체인 검증

에디터 강좌의 원문과 게임 데이터를 바탕으로 가설을 세운 뒤, 실제 맵을 대상 StarCraft 버전에서 열어 재현한다. 아래 점검 항목은 원인 후보를 좁히는 절차이며, 서로 다른 문제를 한 오버레이나 한 수치로 대체하지 않는다.

## 슬롯과 시작 상태

- 맵의 사람 슬롯/컴퓨터 슬롯, 종족, Start Location, 배치된 시작 유닛을 서로 연결한다.
- 로비 종족 선택 설정이 배치 유닛과 트리거 대상에 미치는 영향을 실제 게임에서 확인한다.
- 빈 플레이어 슬롯이 진행 로직/승리 판정에 끼치는 영향을 확인하고, 필요한 초기화와 정리 트리거를 설계한다.

## 전투·피해·고저

- 사거리, 공격 대상(지상/공중), 필요 조건(전력, 탑승 유닛, 모드)은 게임 데이터와 대상 맵 버전에서 확인한다.
- 고지/저지 간 원거리 명중, 이동 연결과 공격 사거리를 서로 다른 문제로 검사한다.
- 유닛 설정 변경은 [unit/settings.md](../unit/settings.md), 피해 배율은 [unit/damage.md](../unit/damage.md)의 출처를 따라 확인한다.

## 조건·상태와 트리거

- `Bring`, `Command`, `Deaths`, `Wait`, `Preserve Trigger`의 세부 런타임은 [관련 원문](https://cafe.naver.com/edac/book5095361/76436)과 기능별 문서를 대조한다.
- 액션 순서와 트리거 소유자는 결과를 바꿀 수 있다. [execution.md](../trigger/execution.md)를 참고하고 상태 전이를 게임에서 검증한다.
- Hyper Trigger 주기나 동시 실행을 전제로 설계할 때는 추정 프레임 값을 정답으로 사용하지 말고 목표 버전의 실제 시간과 부작용을 측정한다.

## 실행/호환성

잘못된 유닛·스프라이트 배치, 좌표, 포맷, 타일 속성은 게임 버전에 따라 실행 실패 원인이 될 수 있다. 알려진 출처 및 재현 절차는 [crashes.md](crashes.md)를 보되, 원문 확인이 안 되거나 상충하는 설명은 미검증으로 다룬다. 맵 저장 후 대상 게임에서 열고 시작해 본다.
