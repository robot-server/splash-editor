# [트리거/로직 패턴]

## 메모리 주소를 EPD 트리거로 읽고 쓰기

- 패턴 이름: Deaths 플레이어 인자에 EPD 주소를 넣어 게임 상태 접근
- 구현하고자 하는 기능: 클래식 트리거가 직접 다루지 못하는 게임 메모리 상태를 읽거나, 특정 바이트/워드만 갱신한다.
- 조건(Condition) 및 액션(Action) 구조 체인: `splash-cli eud offsets` 또는 `eud addr`로 이름 있는 주소를 찾고 `eud check`로 오프셋 표에 따른 정적 진단을 수행한다. 주소를 EPD로 변환해 `Memory`/`Memory Masked` 조건·액션을 구성한다. 기존 메모리 필드를 갱신할 때는 변경 대상의 바이트 폭에 맞는 마스크를 지정하고 결과를 다시 읽어 확인한다.
- 예외 처리/버그 방지 로직: EUD는 사용자 승인 뒤에 쓴다. `eud check`는 실제 게임을 실행해 호환성을 증명하지 않는다. 주소가 정렬되지 않았다면 그 주소를 `--mask`와 함께 직접 쓰지 말고, `eud addr`가 보여 주는 `담긴 칸`의 정렬 주소와 마스크를 사용한다. 오프셋 표에 없는 주소는 지원 여부를 알 수 없으며, 대상 게임 버전에서 직접 시험하기 전에는 안전하다고 단정하지 않는다.

> **먼저 [limits.md](limits.md) 를 읽는다.** EUD 는 사용자 허락을 받고
> 쓰는 것이고, 지켜야 하는 안전 규칙이 있다. 이 글은 **규칙을 지킨다는
> 전제 아래** 원리를 적는다.

## 왜 되는가 — 블리자드가 범위를 안 봤다

`Set Deaths` 는 **플레이어 · 유닛 · 값** 세 칸을 받는다. 그런데 게임이
**그 범위를 검사하지 않는다.**

> "플레이어 221942 의 브루들링 데스값을 29 더한다" 같은 말이 안 되는
> 값을 넣어도 게임이 그대로 받는다.

데스값 표는 게임 메모리 안에 있고, 표 바깥으로 넘어가면 **다른 정보가
있는 자리**를 읽고 쓴다. 그래서 **Extended Unit Death** 다.

## 주소 계산

```
주소 = 0x0058A364 + 4 × (유닛번호 × 12 + 플레이어번호)
EPD  = (주소 − 0x0058A364) / 4
```

유닛을 0 으로 두고 플레이어 자리에 EPD 를 통째로 넣는 것이 관용구다.

```
SetDeaths(EPD(ptr), Modifier, X, 0)   ==   SetMemory(ptr, Modifier, X)
```

우리 CLI 로 확인한다.

```sh
splash-cli eud addr 0x664080      # → EPD 223047, 이름까지 붙여 준다
splash-cli eud epd 223047         # → 0x00664080
splash-cli eud offsets 체력        # 이름으로 찾기
splash-cli eud list 맵            # 맵 안의 EUD 를 전부
splash-cli eud check 맵           # 오프셋 표 기반 정적 진단
```

카페의 공식과 CLI 가 같은 값을 낸다 (0x664080 → 223047). 손으로 계산
하지 않는다.

## 오프셋은 **4바이트 단위**다

한 주소는 4바이트를 한꺼번에 읽고 쓴다.

```
SetMemory(0x100003, Add, 0x42);   ← 비정렬 주소라 직접 쓸 수 없다
```

그래서 `0x100000` 이라고 하면 `0x100000~0x100003` 네 바이트를 말한다.

## **한 주소에 두 정보가 들어 있는 일이 많다**

여기가 EUD 를 처음 만질 때 가장 많이 다치는 자리다.

| 크기 | 무슨 일 |
| --- | --- |
| 4바이트 정보 | 주소 하나 = 정보 하나. 쉽다 |
| **2바이트 정보** | **한 주소에 둘**이 들어 있다 |
| 1바이트 정보 | 한 주소에 넷 |

카페의 예:

```
0x65678C  앞 2바이트 = 골리앗 지상 공격 아이콘
          뒤 2바이트 = 스파이더 마인 공격 아이콘

SetMemory(0x65678C, SetTo, 311);   ← 마인 아이콘을 핵폭발로
```

311 은 `0x00000137` 이다. 뒤 2바이트는 뜻대로 바뀌지만 **앞 2바이트가
0 이 되어 골리앗 아이콘까지 마린 아이콘으로 바뀐다.**

> **옆자리를 지우지 않으려면** `Memory Masked`(비트마스크)를 쓰거나,
> 원래 값을 읽어 더하는 식으로 짠다. 비정렬 주소를 `--mask`와 함께
> 직접 넣으면 CLI가 정렬된 칸으로 바꾸지 않는다. `eud addr <주소>`가
> 출력하는 `담긴 칸` 주소를 `eud set-action`에 넣고, 출력된 마스크를
> `--mask`에 전달한다. 마스크된 값의 비트 위치와 액션 값의 배치는 별도로
> 대조한다.

## 4바이트짜리 쉬운 예

```
0x515BBC = 진동형 공격이 **대형 유닛**에게 들어가는 비율
           기본 64 (= 25%), 256 이 100%
SetMemory(0x515BBC, SetTo, 512);   → 대형에게 오히려 두 배
```

이 자리가 [../unit/damage.md](../unit/damage.md) 의 곱셈표를 정하는
곳이다. **공격 형태 곱셈표는 맵이 못 고친다**고 적었는데, **EUD 로는
고칠 수 있다.** 다만 곱셈이 붙는 순서는 그대로다 — 방어력을 먼저
빼고 그 다음 곱한다 (카페 예제에서 20 → 방어력 빼고 19 → ×2 = 38).

## CP 트릭 — 트리거 수를 줄인다

같은 일을 플레이어·유닛마다 따로 쓰면 트리거가 폭발한다. 카페 예제는
**1700 × 4 개**가 필요한 일을 **1700 + a 개**로 줄인다. `Current
Player` 자리를 옮겨 가며 같은 트리거를 돌려 쓰는 기법이다.

> 이 저장소에서 EUD 를 쓸 일이 생기면 **`eud build` 로 epScript 를
> 얹는 편**이 낫다. 손으로 CP 트릭을 짜는 것보다 안전하고 읽힌다.

## 리마스터에서 안 되는 자리가 있다

오프셋은 게임 판본을 탄다. **EUD Book 에 적힌 것도 리마스터에서
지원되지 않는 것이 있다.**

```sh
splash-cli eud check 맵     # 오프셋 표 기반 정적 진단
```

이 명령은 주소 정렬과 오프셋 데이터베이스의 `Unsupported`/`ReadOnly`
표시를 검사한다. 표에 없는 주소는 unknown이며, 실제 리마스터 실행의
성공 여부를 판정하지 않는다. 결과를 검토한 뒤에도 대상 게임 버전에서
맵을 열고 기능을 시험한다 — [limits.md](limits.md)의 안전 규칙을 따른다.
