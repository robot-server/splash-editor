# 밀리 지형 자동 생성에서 확인한 실패 원인

## [지형/배치 메커니즘]

- 메커니즘 이름: 경로 그래프와 지형 윤곽을 분리해 계획
- 적용 이유/목적: 수치상 면적·대칭이 맞아도 플레이 공간이 사람 손으로 설계한 지형처럼 보이거나 전략적으로 기능한다는 보장은 없다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 먼저 시작점, 확장, 초크, 고저 전환, 중앙 목표를 공간 그래프로 정한다. 그 후 ISOM 윤곽을 그려 각 연결부를 지형 타일 및 램프와 맞춘다. 타일 수치의 균등 분포나 회전 복제만으로 절벽 윤곽을 만들지 않는다. 대칭이 필요하면 각 변환 위치에 맞는 ISOM 경계 방향으로 다시 그린다.
- 잘된 예시 및 실패하는 나쁜 예시: 각 고저 구역이 확장·방어·교전의 역할을 가지며 연결 그래프와 실제 통로가 일치하면 성공 후보다. 중심에서 꽃잎처럼 반복되는 방사형 윤곽은 면적·대칭 지표가 맞아도 전략 공간이 단조로우므로 실패 예다. 이 실패 유형은 자동 생성 시험에서 관찰됐다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: ISOM은 지형 연결과 고저 경계를 표현한다. 램프는 주변 저지·고지에 연결된 walkable 통로인지 배치 후 다시 확인한다.
- 유닛 길막/동선 보장 규칙: 생성된 지도에서 시작점 간, 시작점과 주요 확장 간 지상 이동성을 검사한다. 로컬 램프 조각의 통행 검사만으로 전체 경로 폭·착지 공간을 보증하지 않으므로 실제 유닛 크기의 통과를 확인한다.

이는 생성 실패에서 얻은 제한 사항이지, 사람이 만든 밀리맵의 보편적인 수치 법칙이 아니다. 구현과 검사 범위는 `.agents/skills/starcraft-map/scripts/melee_shape.py`, `scmap.py`를 확인한다.
