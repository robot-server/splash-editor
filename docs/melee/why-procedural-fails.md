# 밀리맵 지형을 절차적으로 만들면 왜 실패하는가

**이 글은 실패 기록이다.** 세 번 시도해 세 번 다 슬롭이 나왔다. 왜
그랬는지와, 다음에 무엇을 해야 하는지를 적는다. 같은 길로 다시 들어가지
않기 위한 글이다.

밀리맵 지형을 생성하려 든다면 **먼저 이 글을 읽는다.**

---

## 1. 무엇을 해 봤고 어떻게 실패했나

| 시도 | 방법 | 결과 |
| --- | --- | --- |
| 1 | 절차적 덩이(blob) 생성 | 네모난 언덕 + 흩뿌린 장식. 기계 티 |
| 2 | 통계 맞춤 — 타일그룹 수·두뎃 수·주기성을 실측 중앙값에 맞춤 | **수치는 맞고 그림은 틀림** |
| 3 | 실제 맵에서 24x24 바닥 조각을 떠서 격자로 깔기 | 조각보 누더기, 절벽 끊김 (가장 나쁨) |
| **4** | **§4 파이프라인 — 원판 합집합 + 형태 연산으로 곡률을 못 박고, 형상 지표 세 개를 실측 대역에 맞춤** | **지표 셋 다 통과, 그림은 꽃잎 열여섯 장짜리 눈송이.** 시도 2 의 재현 |
| ○ | 실제 맵에서 본진 34x34 를 통째로 떠서 붙이기 | **유일하게 됨** (다만 남의 저작물) |

시도 2 가 특히 뼈아프다. 실측값을 다 맞췄는데도 슬롭이었다. 사용자의
표현으로 "AI 음식 사진" 이다.

---

## 2. 왜 실패했나 — 원인 셋

### (가) 전역 통계는 좋은 설계의 *증상*이지 *원인*이 아니다

"타일 그룹 504종, 두뎃 91개, 주기성 4.3%" 는 잘 만든 맵을 **재고 나서**
나오는 수다. 그 수를 목표로 삼아 거꾸로 만들면 수치만 맞는 것이 나온다.
증상을 맞춰도 병이 낫지 않는다.

### (나) 생타일은 설계 언어가 아니라 **출력 포맷**이다

사람 맵퍼는 타일 번호를 한 장씩 고르며 맵을 설계하지 않는다. 영역과
동선을 먼저 정하고, 타일은 마지막에 그 결정을 **실현**할 뿐이다.
타일 층에서 설계하려 들면 설계가 표현되지 않는다.

### (다) 슬롭은 국소도 전역도 아닌 **중간 스케일**에 산다

- **국소**(타일 접합): ISOM 브러시가 이미 공짜로 완벽하게 해 준다.
- **전역**(스타팅 수, 대칭, 러시 거리): 제약으로 못 박으면 된다.
- **중간**(영역의 모양, 절벽선의 곡률, 본진↔앞마당↔센터의 비율):
  **아무도 안 맡고 있었다.** 슬롭은 전부 여기서 나왔다.

시도 1 의 "네모난 언덕" 은 타일 배치가 틀려서가 아니다. ISOM 이
칠했으니 타일 배치는 완벽했다. **언덕의 윤곽이 네모**여서 틀렸다.

## 3. 하지 말 것

### ✗ WFC (Wave Function Collapse) 를 주 생성기로 쓰지 말 것

그럴듯해 보이지만 **이 문제에는 맞지 않는다.**

- **이미 가진 것을 비싸게 다시 만든다.** WFC 가 보장하는 것은 "국소적
  으로 실제 맵과 같은 타일 배치" 인데, 실제 맵 182장이 전부 같은 ISOM
  솔버로 그려졌으므로 ISOM 브러시가 이미 그걸 공짜로 준다.
- **격자가 다르다.** ISOM 은 타일 격자가 아니라 마름모 격자 위에서
  움직인다. 정사각 타일 인접성으로 학습하면 틀린 문법을 배운다.
- **램프를 표현할 수 없다.** 램프는 6x6 강체 블록이고 방향마다 값이
  다르다. 장거리 강체성은 WFC 가 구조적으로 가장 못하는 일이다.
- **128x128 에서 안 풀린다.** 대칭 + 연결성 + 스타팅 고정 + 러시거리를
  모두 하드 제약으로 얹으면 모순과 백트래킹 폭발이 온다.
- **풀려도 균질하다.** 큰 맵에서 WFC 는 무계획하고 "samey" 한 그림을
  낸다 — 시도 2 를 다른 알고리즘으로 재현하는 것이다.

WFC 를 쓸 자리는 **마지막 다듬기뿐이다**: 이미 정해진 평지 안에서 변종
고르기, 정해진 절벽 띠의 미세 타일 고르기, 장식 배치.

### ✗ "패치 커버리지" 를 판정기로 쓰지 말 것

실제 맵의 4x4 타일 패치로 사전을 만들고 후보의 패치 중 몇 %가 사전에
있는지 재는 방법이다. 그럴듯하지만 **재 봤더니 죽은 지표였다.**
정글 128x128 실맵 15장으로 사전을 만들어 실제로 계산한 값이다.

**(가) 정확한 타일로 재면 실맵끼리도 안 겹친다**

| 잰 것 | 값 |
| --- | --- |
| 15장을 합친 4x4 창 | 234,375개 |
| 그중 서로 다른 패치 | **232,321개** (창마다 거의 유일) |
| 한 장을 빼고 나머지 14장으로 그 한 장을 채점 | **중앙값 0.2%** |

스타일 모델이 아니라 **지문 데이터베이스**다. 새 실맵도 0점이고
복사본만 100점이다. 즉 **최적해가 표절이다.**

**(나) 그룹으로 재면 순위가 뒤집힌다**

| 맵 | 그룹 4x4 커버리지 |
| --- | --- |
| **절차 생성 슬롭 (빈 네모 고지)** | **98.2%** |
| 공식 맵 (leave-one-out) | **50.8%** |

**빈 흙 맵이 공식 맵을 이긴다.** 까닭은 ISOM 평지가 그룹 짝(2↔3, 4↔5)
체커보드라, 흙만 칠하면 사전에서 가장 흔한 패치로 도배한 셈이 되기
때문이다. 슬롭은 창의 90.7%가 그 한 쌍이고 공식 맵은 2.2%다.

**(다) "뿌리면 못 속인다" 는 거꾸로다**

두뎃과 변종을 뿌리면 정확 4x4 는 **더** 유일해져서 점수가 **떨어진다.**
좋은 밀리맵일수록 커버리지가 낮다. 지표의 기울기가 목표와 반대다.

**(라) 파손을 못 잡는다**

| 파손 | 자기 사전 기준 점수 |
| --- | --- |
| 공식 맵을 32x32 블록으로 섞기 (능선 파괴) | 86.7% |
| 램프 둘레 12x12 만 섞기 (입구 사망) | 94.4% |

게다가 4x4 창은 6x6 램프도 34x34 본진도 담지 못한다. **실제로 겪은
버그(자원 0, 램프 안 통함, 미네랄이 입구를 막음)를 하나도 못 잡는다.**
창을 8x8·16x16 으로 키우면 그룹으로 재도 실맵 간 공유가 0.1%/0.0% 다 —
설계가 사는 스케일에서 정확 일치는 **복제 탐지기**일 뿐이다.

### ✓ 대신 이것을 쓴다 — 형상 통계

멤버십(사전에 있나)이 아니라 **형상**을 재면 갈린다. 직접 재서 확인했다.

| | 균일 창 % | 고지 덩이 bbox 채움 |
| --- | --- | --- |
| 공식 맵 (Polypoid) | **5.9%** | **0.40~0.42** |
| 공식 맵 (Lost Temple) | 18.1% | 0.61~0.75 |
| 공식 맵 (Fighting Spirit) | 3.1% | — |
| 조각 붙이기 시도 | 68.8% | 0.65~0.78 |
| **절차 생성 슬롭** | **90.7%** | **0.90~0.91** |

- **균일 창 %** — 4x4 창이 지형 한두 가지로만 이루어진 비율. 높으면
  절벽도 수풀도 없는 벌판이다.
- **bbox 채움** — 고지 덩이가 제 외접 사각형을 얼마나 채우는가.
  1.0 이면 완전한 직사각형. **네모난 언덕이 여기 걸린다.**

`verify_map.py` 가 이 둘을 잰다 (`-- 지형 형상 --` 절). 공식 맵은
통과하고 앞서 만든 슬롭은 둘 다 걸린다.

**다만 이것도 미감을 재지는 못한다.** "이 능선이 어색한가" 는 여전히
못 가린다. 직선 4칸은 실맵에도 있다 — 어색함은 20칸이 안 꺾이는 쪽에
있다. 이 둘은 **바닥을 치는 검사**이지 좋은 맵의 증명이 아니다.

## 4. 할 것 — 기능 그래프부터

사람 맵퍼, 상용 엔진, 학계 연구가 **독립적으로 같은 순서**를 지목한다.

| 출처 | 순서 |
| --- | --- |
| 숙련 맵퍼 | 개념 → 확장 배치 → 동선 → 비율 맞춘 스케치 → **한 코너만** → 회전 복사 → 그제야 타일 → 장식 |
| AoE2 랜덤맵 (상용 25년) | Land → Elevation → Cliffs → Terrain → **Connections** → Objects |
| PSMAGE (학계) | 영역(Voronoi) → 고도 → 스타팅 → 확장 → 대칭 → 실현 |

그래서 이렇게 한다:

```
기능 그래프  (본진·앞마당·센터·외곽길·확장을 노드와 통로로)
   ↓
공간 배치    (대칭 아래 2D 임베딩, 통로 폭·러시 거리 최적화)
   ↓
높이 영역    (저지대/고지대 마스크)
   ↓
절벽 윤곽    (경계를 곡선으로. 아래 불변식을 박는다)
   ↓
ISOM 래스터화 (곡선 → 마름모 격자로 양자화 → 붓질 목록 → isom-batch)
   ↓
램프 삽입    (원자적 prefab. 자리는 윤곽 단계에서 미리 예약)
   ↓
타일 변종·장식 (여기서만 패치 합성을 쓴다)
   ↓
검증 → 실패하면 타일이 아니라 곡선 파라미터로 되돌린다
```

### 미감은 채점하지 말고 **불변식으로 못 박는다**

"직선을 피하고 둥근 모서리를 쓴다" 는 숙련 맵퍼의 첫 번째 원칙이다.
이걸 사후 채점 항목이 아니라 **생성기 불변식**으로 만든다:

- 최소 곡률 반경 ≥ k 타일
- 길이 L 이상의 직선 절벽 금지
- 예각 코너 금지
- 램프가 들어갈 평탄 구간을 **윤곽 단계에서 미리 예약**

지금은 램프를 다 만든 뒤 억지로 끼워 넣어 터진다. 자리를 먼저 잡으면
그 싸움이 사라진다.

### 대칭이면 **1/N 만 만든다**

4인용이면 한 코너만 잘 만들고 회전 복사한다. 128x128 전체를 한 번에
만드는 것은 네 배 어려운 문제를 스스로 만드는 짓이다.

단, **`terrain mirror` 로 절벽을 베끼지 않는다** — 타일 값만 옮겨서
절벽 방향이 뒤집힌다. **붓질 목록을 회전 좌표에 다시 놓는다.**

### 스탬프는 버리지 말고 **직접 그려서** 쓴다

유일하게 성공한 방법이다. 성공한 이유는 크기가 아니라 **본진이 완결된
기능 단위**이기 때문이다. 남의 맵에서 복제하는 대신:

1. 치수는 실측에서 가져오고 (`scmap.MAIN_*`, `data/corpus.json`)
2. 본진 한 벌을 **직접** 잘 만들어 타일셋별로 몇 종 갖춘다
3. 테두리 2타일을 평지·낮은 높이·걷기 가능으로 **정규화**한다
   (경계 계약 — 이러면 이음매가 늘 맞는다)
4. 대칭 회전으로 N 곳에 놓고 나머지는 위 파이프라인으로 만든다

## 5. "눈" 은 세 겹으로 나눈다

하나의 점수로 세 가지 다른 질문을 풀려 해서 실패했다.

| 층 | 묻는 것 | 자동화 | 방법 |
| --- | --- | --- | --- |
| **파손** | 게임이 되는가 | **완전 가능** | 미니타일 길찾기, 자원 도달, 램프 연결, 건설 면적. **이미 있다** (`verify_map.py`) |
| **게임플레이** | 공평하고 재미있나 | **가능** | 러시 거리 분산, 초크 폭, 확장 안전도, 자원 총량, 스타팅 간 비대칭 |
| **형상** | 벌판인가, 언덕이 네모난가 | **가능** | 균일 창 %, bbox 채움 (§3) — `verify_map.py` 가 잰다 |
| **미감** | 능선이 어색한가 | **불가. 포기** | 구성으로 보장(§4) + 렌더를 사람이 본다 |

> 렌더를 볼 때는 **타일 그림이 아니라 고도 색칠로** 본다. 두뎃이 눈을
> 속인다 — 장식이 깔리면 네모난 언덕도 그럴듯해 보인다.

### 판정기를 만든다면 — 먼저 파손 세트로 검증한다

**이 시험을 통과하기 전에는 어떤 점수도 생성 최적화에 연결하지 않는다.**
결함 있는 판정기를 최적화하면 더 교묘한 슬롭이 나올 뿐이다.

정상 맵에 인위적 파손을 가한 세트를 만든다:

- 조각을 섞기
- 절벽을 한 칸 끊기
- 램프를 옆으로 옮기기
- 같은 패치를 반복해 도배
- 긴 능선을 뒤집기

패치 커버리지는 이 시험을 **이미 떨어졌다** (§3 라). 형상 두 지표는
통과한다 — 슬롭 90.7% 대 공식 맵 5.9%.

**판정기가 이것들을 실제 맵보다 일관되게 낮게 매기는가?** 못 매기면
그것은 눈이 아니다.

## 5.5 시도 4 — 파이프라인을 실제로 짜 보고 알게 된 것

§4 가 지목한 순서대로 `scripts/melee_shape.py` 를 짰다. 만들면서 **내
지표가 두 번, 실측 기준이 세 번 틀렸다.** 그 기록이 아래다. 다음에
같은 길로 들어가지 않으려면 이걸 먼저 읽는다.

### (가) 도구 사실 — 확인해서 고친 것

ISOM 래스터화를 처음에 **"가로 짝수 칸마다"** 찍었는데 틀렸다.
chkdraft 의 `Chk::IsomDiamond` 를 읽어 확인한 바:

```
마름모 = (i, j),  유효 조건 (i+j) % 2 == 0
타일 평면 중심  = (2i, j)
붓질 픽셀 좌표  = (64i, 32j)
```

즉 **줄마다 엇갈린다**: j 짝수면 x = 0, 4, 8…, j 홀수면 x = 2, 6, 10….
"가로 2타일, 세로 1타일" 은 이웃 마름모 사이 벡터가 `(±2, ±1)` 이라는
뜻이지 `(2,1)` 직사각 격자를 훑으라는 뜻이 아니다. 짝수 칸마다 찍으면
같은 마름모를 두 번 찍고 엇갈림을 무시한다.

그리고:

- **브러시는 1 로 못 박는다.** 큰 브러시는 경계를 예측하기 어렵게 넓힌다.
- 마름모 중심 격자의 덮기 반경이 약 **1.25 타일**이다. 지키고 싶은 통로
  폭·목 폭은 **목표보다 2.5 타일 넓게** 잡아야 양자화에 안 먹힌다.
- **rot90 은 ISOM 격자의 정확한 대칭이 아니다.** 이웃 벡터 `(±2,±1)` 이
  90도 돌면 `(±1,±2)` 가 되어 같은 격자에 안 맞는다. 마스크가 대칭이어도
  양자화 뒤 1~2 타일 어긋날 수 있다. **타일 단위 완전 대칭이 필요하면
  2인용(rot180) 이 안전하다.**
- `isom-batch` 는 일부 붓질이 실패해도 나머지를 계속 한다. "놓지 못한
  것 N" 이 0 이 아니면 실패로 다뤄야 한다.

### (나) 곡률은 점수가 아니라 형태 연산으로 못 박을 수 있다 — 이건 됐다

반지름 r 원판으로 **열고 닫으면**(opening + closing) r 보다 얇은 돌출과
홈이 사라진다. 경계 곡률 반경이 어디서나 r 이상이 되므로 사후 채점이
필요 없다. 램프 자리는 먼저 찍어 **얼려** 두면 연산이 건드리지 않는다.
이 장치는 실제로 작동했다 — 네모난 언덕도, 예각 코너도 안 나온다.

### (다) 기준을 잡는 데 세 번 틀렸다 — 고도 문턱은 타일셋마다 다르다

§3 의 "균일 창 3~18%, bbox 채움 0.40~0.75" 는 **타일 종류**로 잰 값이다.
내 형상 층은 고지/저지 두 값뿐이라 같은 자가 아니다. 같은 자로 다시
재려다 세 번 틀렸다.

| 재는 법 | 공식 맵 균일 창 | 공식 맵 고지대 | 왜 틀렸나 |
| --- | --- | --- | --- |
| 고지 = 고도 2 이상 | 65.0% | 3% | Jungle·Ice 등에서 "High \*" 가 고도 **1** 이라 고지대를 거의 못 셈 |
| 고지 = 고도 1 이상 | 65.0% | 41% | Space 는 **평지(Platform)가 고도 1** 이라 발판 전체를 고지로 셈 |
| 고지 = 고도 2, 이진화 | 93.6% | 3.4% | 위와 같은 병. Fighting Spirit·Lost Temple·Tau Cross·Luna 가 **"고지대 0.0%"** 로 나왔다 — 램프가 있는 맵에 고지대가 없을 수는 없다 |

짐작을 멈추고 `measure_terrain_types.py` 로 **지형 종류를 하나씩 ISOM
으로 칠해 보고** 어떤 고도가 나오는지 쟀다 (`data/terrain-types.json`).

| 타일셋 | 저지대 | 1단 고지 | 2단 고지 | **고지 문턱** |
| --- | --- | --- | --- | --- |
| Badlands · Ashworld | 고도 0 | **없음** | High \* = 고도 2 | **2** |
| Space Platform | Space·Low Platform = 0 | **Platform·Plating = 1 (평지!)** | High Platform = 2 | **2** |
| Jungle · Desert · Ice · Twilight | 고도 0 | **High \* = 1** | 드문 3단(High Temple 등) = 2 | **1** |
| Installation | 고도 0 | Floor·Plating = 1 (평지) | 없음 | 고지대 없음 |

그 문턱으로 다시 재서 나온 **최종 기준값** (공식·리그 밀리맵, 이름
중복 제거):

```
균일 창    중앙 65.0%   사분위 61.8~71.4
고지대     중앙 36.4%   사분위 32.6~42.2
bbox 채움  중앙 0.55    사분위 0.42~0.63
```

**교훈은 지표를 고르는 법이 아니라 재는 법이다.** "고도" 라는 칸이
있으니 그걸 쓰면 되겠다고 세 번 짐작했고 세 번 다 틀렸다. 칠해 보고
재는 데 든 시간은 몇 분이었다.

### (라) 기준이 맞아도 그림은 틀릴 수 있다 — 눈송이

`design()` 은 고른 각도로 덩이 스물 몇 개를 놓아 **최종 기준값 셋을 다
통과했다** (고지 37% · 균일 창 64% · bbox 중앙 0.51). 그려 보니
**꽃잎 열여섯 장짜리 눈송이**였다. 맵으로 보이지 않는다.

즉 §3 이 미리 적어 둔 "**바닥을 치는 검사이지 좋은 맵의 증명이 아니다**"
가 그대로 확인됐다. 지표를 목표로 삼아 맞추면 지표를 통과하는 눈송이가
나온다 — 시도 2 와 같은 병이고, 알고리즘만 바뀌었다.

병의 자리는 래스터화가 아니라 **설계**였다. 실제 맵의 고지대는 고른
각도로 흩어진 덩이가 아니라 **이름이 있는 몇 개의 자리**다 — 본진 언덕,
앞마당, 센터 능선, 확장. 그렇게 다시 짠 `design_lanes()` 는 그림이
맵처럼 읽히는 대신 지표가 대역을 벗어난다 (고지 19~27%, 균일 창 79~86%).

**둘 중 어느 쪽도 아직 맵이 아니다.** 지표를 맞추면 눈송이, 배치를
맞추면 밋밋하다. 남은 것은 (마) 다.

### (마) 다음에 할 것

1. **고지대의 정의를 이름으로 잡는다.** 고도 숫자가 아니라 지형 종류
   이름("High *", "Raised *")으로 갈라야 한다. `measure_terrain_types.py`
   가 종류마다 ISOM 으로 칠해 보고 어떤 그룹·고도가 나오는지 재
   `data/terrain-types.json` 에 남긴다. 그 표로 다시 재야 기준이 선다.
2. **기준이 서기 전에는 어떤 지표도 생성 최적화에 연결하지 않는다.**
   §5 가 이미 적어 둔 규칙이고, 이번에 그걸 어겨서 눈송이가 나왔다.
3. 설계는 `design_lanes()` 쪽 — 이름 있는 자리 — 이 맞다. 다듬을 것은
   그쪽이다.
4. 자문(codex)이 짚은, 아직 안 한 것: 마스크를 원본으로 삼지 말고
   **연속 좌표계의 원호 체인**을 원본으로 두기, sagitta 로 긴 직선 막기,
   램프를 타일셋·방향별 **stencil 로 미리 측정**해 두기, 붓질 뒤 MTXM 을
   다시 읽어 위상 보존을 검사하기.

## 6. 지금 할 수 있는 것

밀리맵 자동 생성은 **아직 안 된다.** 억지로 내놓지 말고 사용자에게
사실대로 말한다. 대신 이건 된다:

- **검증·수리** — `verify_map.py` 로 재고, 파손을 짚고, 고치기
- **실제 맵 편집** — 있는 맵에서 지형·유닛·트리거를 고치기
- **본진 스탬프 붙이기** — 사용자가 가진 맵에서 떠서 쓰기
- **유즈맵** — 지형이 직사각 기하라 계산으로 정확히 만들 수 있다.
  내용은 트리거이고 트리거는 글이라 짜고 검증할 수 있다.
  `make_square_defense.py` 를 본보기로 쓴다.
