# 밀리맵 자리와 종족 밸런스 검토

## [지형/배치 메커니즘]

- 메커니즘 이름: 시작 자리에서 확장으로 이어지는 선택지 설계
- 적용 이유/목적: 밀리맵의 밸런스는 단일 자원 숫자가 아니라 본진 방어, 확장 진입, 이동 경로와 고저를 함께 경험한 결과다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 각 시작 자리에 대해 본진, 첫 확장, 외곽 확장, 중앙으로 나가는 경로를 지도 위에 표시한다. 같은 종류의 자리가 같은 방향의 공격과 확장 압박을 받는지 대칭 좌표에서 대조한다. 비대칭 설계면 의도한 보상과 위험이 플레이에서 서로 대응하는지 기록한다. 확장 위치는 [resource-sites.md](resource-sites.md)의 건설·애드온·채집 검사를 통과해야 한다.
- 잘된 예시 및 실패하는 나쁜 예시: 자원 이점이 있는 자리가 그만큼 노출되거나 먼 방어 동선을 가지며, 상대도 대응할 공격 선택이 있으면 검토 가능한 설계다. 자원량만 같고 한쪽은 짧은 안전 경로, 다른 쪽은 긴 단일 진입로인 자리는 동등하다고 단정하지 않는다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 고지 진입과 중앙/확장 연결은 실제 walkability를 따라 검증한다. 대칭 맵에서 경계와 통로 방향도 대응해야 한다.
- 유닛 길막/동선 보장 규칙: 각 스타팅과 확장에서 일꾼 및 전투 유닛을 실제로 이동시켜 도착 가능성과 병목을 확인한다. 정적 거리나 연결 오버레이만으로 경쟁 시간·채집 효율을 확정하지 않는다.

## [트리거/로직 패턴]

- 패턴 이름: 밀리 초기화와 승패 판정을 별도 조건 체인으로 처리
- 구현하고자 하는 기능: 시작 자원을 지정하고, 건물을 모두 잃은 플레이어의 패배와 동맹 밖 상대가 모두 제거된 뒤의 승리를 판정한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 실제 밀리 원본에서 `Always()` → `Set Resources(Current Player, Set To, 시작 광물)`이 별도 트리거로 실행됐다. 승패는 `Command(Current Player, Buildings, At most, 0)` → `Defeat()`와 `Command(Non Allied Victory Players, Buildings, At most, 0)` → `Victory()`를 나눠 구성했다. 오프닝 소리와 맵 타이틀 문구도 별도 `Always()` 트리거에 있었다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): `Current Player`와 `Non Allied Victory Players`는 서로 다른 대상 범위다. Force 구성·동맹 승리 설정을 바꾸면 조건이 의도한 생존자 집합을 검사하는지 다시 확인한다. 이 원본 관찰은 [한 scmscx 밀리맵의 트리거](https://scmscx.com/map/7x9t59z8) 사례이지 모든 밀리맵의 필수 구현은 아니다. 같은 원본의 `Always()` 자원 설정과 오프닝 연출도 각자 별도 트리거로 분리되어 있다.
