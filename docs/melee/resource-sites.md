# [지형/배치 메커니즘]

## 멀티 기지와 자원 접근을 하나의 자리로 설계

- 메커니즘 이름: 기지 발자국·애드온 칸·채집 접근을 묶은 자원 포켓
- 적용 이유/목적: 미네랄과 가스가 보여도 기지 건물이나 일꾼 동선이 성립하지 않으면 확장으로 기능하지 않는다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): Start Location은 본진 건물 발자국의 의도한 시작 칸으로 둔다. Command Center·Nexus·Hatchery의 건설 발자국은 각각 4×3 타일이다. 미네랄·가스는 일꾼이 접근할 면과 기지 사이 경로를 확보하며 기지 발자국과 겹치지 않게 놓는다. Terran 기지에서는 Command Center의 오른쪽 아래 애드온 접속부 옆에 2×2 타일의 추가 여유를 남긴다. 이 공간을 자원·절벽·걷기 차단 doodad가 침범하면 애드온이 들어가지 않는다. 자원마다 일꾼이 접근할 수 있는 면이 남아야 한다. Pathfinder Regions로 연결 후보를 확인하되, 미니타일 이동성만으로 채집 최단 경로를 증명했다고 간주하지 말고 게임에서 일꾼을 보내 왕복 채집을 확인한다. SCMDraft `Invalid Resource`, `Invalid Depot` 오버레이는 금지 칸을 찾는 데 쓰고 `Pathfinder Regions`는 연결이 끊긴 구역을 찾는 데 쓴다.
- 잘된 예시 및 실패하는 나쁜 예시: [스타 에디터 아카데미의 밀리맵 필수 요소](https://cafe.naver.com/edac/book5095361/76350)는 시작 지점을 본진 자리로 놓고 중립 자원과 함께 설계하는 순서를 설명한다. 성공 자리는 기지 건물과 필요한 애드온 공간이 유효하고, 모든 자원에 일꾼이 접근해 채집한다. 실패 자리는 자원은 놓였지만 본진 건물 발자국이 걸리거나, 테란 애드온 쪽을 바위·절벽·자원이 막거나, 일꾼이 자원에 닿지 못한다.

## 고저 경계와 통과 가능한 램프

- 메커니즘 이름: ISOM으로 절벽 경계를 잇고 램프 지형으로 통로를 연다
- 적용 이유/목적: 고저 차이는 시야·방어·진입 방향을 만든다. 장식상 경사처럼 보이는 것만으로 지상 유닛 통행이 확보되지는 않는다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 고지와 저지의 연결 위치를 먼저 정하고, 양 끝이 각 고도에 실제로 닿는 램프 경로를 만든다. 진입·이탈부의 이동 가능 타일을 확인한다. SCMDraft `Height Transition`은 경사 진입 표시, `Pathfinder Regions`는 보행 영역과 링크 진단에 사용한다. 두 오버레이는 에디터 강좌가 설명하는 진단 표시이므로 최종 플레이 통과를 대신하지 않는다. 회전 대칭을 만들 때는 지형 붓질의 고저·경계 방향을 재구성하고, 이미 완성한 타일 배열을 단순 반전하지 않는다.
- 잘된 예시 및 실패하는 나쁜 예시: 양 끝이 서로 다른 고도의 통로와 연결되고 유닛이 양방향으로 통과하는 램프가 성공 예다. 후보 램프 조각이 통행 가능하다는 사실만으로 주변 고저와 연결된다고 판단하거나, 장식 계단을 막힌 절벽 위에 얹는 것은 실패다.

## 원본 밀리맵에서 고저·통로·중앙 공간 읽기

- 메커니즘 이름: 전장 역할에 따라 개방 구역과 우회로를 나누기
- 적용 이유/목적: 타일 표면을 먼저 채우지 않고 시작 자리·확장·교전 구역이 어떤 길로 이어지는지 정한 뒤 지형 모양을 붙인다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): [scmscx 원본 렌더](https://scmscx.com/map/2BzqG3Bd)는 중앙의 넓은 교전 면과 가장자리의 갈라진 지형 덩이·고저 전환을 함께 둔다. 다른 [원본 렌더](https://scmscx.com/map/7x9t59z8)는 중앙 고지와 여러 진입부를 축으로 본진 사이의 경로를 조직한다. 두 사례에서 복사할 것은 윤곽이 아니라 `본진→확장`, `본진→중앙`, `중앙→상대`의 경로 관계다. 각 관계에 직선 접근, 측면 접근, 방어 가능한 지점을 표시한 뒤 ISOM 경계와 램프를 배치한다. 대칭은 시작자리 공정성을 맞추는 데 쓰고, 모든 모서리와 장식 덩이를 같은 도형으로 반복하지 않는다.
- 잘된 예시 및 실패하는 나쁜 예시: 중앙 전투 공간이 읽히고 외곽 지형이 시야·방어·우회 역할을 맡으며 각 역할이 통로로 연결되면 성공이다. 가운데에서 꽃잎처럼 같은 굴곡을 복제하거나 랜덤 타일만 흩뿌려 동선·시야·확장 관계가 없는 지형은 실패다. 두 원본은 서로 다른 타일셋·윤곽을 쓰면서도 경로와 고저를 중심으로 공간을 구분한 사례다.

# [에디터 타일/배치 제약사항]

## 건설 가능 영역과 이동 연결을 교차 진단

- 지형 간 연결 규칙: 지상 통로는 미니타일 이동 속성으로 연결되어야 한다. 시각 타일의 색이나 이름만으로 walkability를 판정하지 않는다.
- 유닛 길막/동선 보장 규칙: SCMDraft의 [오버레이 및 디스플레이 옵션 강좌](https://cafe.naver.com/edac/book5095361/76372)에 나온 `Invalid Resource`, `Invalid Depot`, `Pathfinder Regions`, `Height Transition`을 용도별로 켜 건설 불가 칸, 자원/본진 footprint, 보행 영역 연결, 경사 진입부를 살핀다. 그런 다음 실제 종족 건물과 일꾼으로 배치·채집을 확인한다. Pathfinder 연결선은 경로 탐색 영역의 연결을 진단할 뿐, 일꾼의 채집 동작이나 최단 경로를 보증하지 않는다.

출처: [강좌 원문 76350](https://cafe.naver.com/edac/book5095361/76350), [강좌 원문 76372](https://cafe.naver.com/edac/book5095361/76372). 건물 발자국과 애드온 여유 칸은 StarCraft 설치 데이터 및 에디터 배치 오버레이에서 확인한다. 생성 스크립트의 `place_base`가 애드온 footprint와 게임 내 일꾼 채집을 검사하지 않는다는 점은 코드 확인 사항이며, 이를 게임 엔진 규칙으로 일반화하지 않는다.
