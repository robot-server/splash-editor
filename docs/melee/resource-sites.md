# [지형/배치 메커니즘]

## 멀티 채집 포켓

- 메커니즘 이름: 기지 건물·자원·일꾼 경로를 한 자리로 묶기
- 적용 이유/목적: 자원이 화면에 놓여 있어도 기지가 들어가지 않거나 일꾼이 닿지 않으면 멀티로 기능하지 않는다. 세 종족 기지와 자원 채집을 동시에 만족시킨다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 자원 발판은 건설·이동 가능하고 같은 고도에 둔다. 커맨드 센터·넥서스·해처리의 4×3 발자국이 자원과 겹치지 않게 예약한다. 테란은 애드온이 붙는 쪽에 2×2 빈 공간을 추가로 둔다. 자원 각 지점부터 기지 채집 면까지 미니타일 이동 경로를 잰다. 절벽·물·통행 차단 두뎃이 우회를 만들거나 경로를 끊으면 자원이나 접근로를 옮긴다. 앞마당 진입로와 자원 포켓, 확장 사이 길은 이어 두고 의도하지 않은 광물벽을 만들지 않는다.
- 잘된 예시 및 실패하는 나쁜 예시: 잘된 자리는 세 종족 기지와 테란 애드온 칸이 비어 있고 모든 미네랄·가스까지 걸어서 닿는다. 나쁜 자리는 미네랄·가스는 있지만 커맨드 센터가 안 들어가거나, 애드온 칸이 절벽/자원에 막히거나, 특정 가스에만 긴 우회로가 생긴다. 현재 `scmap.place_base` 는 자원 건설 가능 여부와 기지 후보만 확인하고 애드온 칸·실제 최단 경로는 검사하지 않으므로 반환 성공을 완성 판정으로 쓰지 않는다.

## ISOM 고저 경계와 램프 두뎃

- 메커니즘 이름: 절벽 윤곽은 ISOM 붓질, 통로는 방향이 맞는 램프 두뎃
- 적용 이유/목적: ISOM은 고저 지형의 경계를 만들고 램프 두뎃은 경계를 통과할 길을 만든다. 둘 중 하나만 있으면 절벽이 막히거나 어색한 경사 단차가 된다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 낮은 지형과 높은 지형의 경계선을 먼저 정하고 램프의 출구를 저지, 입구를 고지에 맞춘다. 램프 양 끝에 병력이 모여 방향을 바꿀 착지 평지를 남긴다. 회전 대칭은 타일 값을 뒤집지 말고 ISOM 붓질의 중심·방향을 회전 좌표에서 다시 적용한다. 맵 타일셋의 후보 두뎃이 정적 길찾기를 통과해도 실제 고저 경계와 주변 지형에 놓고 나서 미니타일 길찾기를 다시 한다.
- 잘된 예시 및 실패하는 나쁜 예시: 잘된 램프는 양 끝의 고저 전환선이 계단 방향과 맞고 착지부가 주 통로로 이어진다. 나쁜 램프는 후보 목록의 통과 가능 표시만 믿고 평지나 엉뚱한 고도에 놓거나, 방향만 맞춘 뒤 착지 공간을 만들지 않는다.

# [에디터 타일/배치 제약사항]

## 자원·기지·걷기 오버레이로 교차 확인

- 지형 간 연결 규칙: Height Transition은 실제 고도 경계에서만 램프 두뎃의 입구·출구와 겹쳐야 한다. 평지 타일 사이에 계단 모양을 장식처럼 놓지 않는다.
- 유닛 길막/동선 보장 규칙: SCMDraft의 Invalid Resource와 Invalid Depot 표시로 자원 및 본진 건물 배치 불가 칸을 확인하고, Pathfinder Regions로 각 자원과 기지·주 통로가 같은 보행 경로에 속하는지 본다. 오버레이는 후보를 찾는 진단 도구다. 최종 자리는 실제 미니타일 길찾기와 자원 건설 가능 검사로 다시 확인한다.
