# 지형의 시각적 구분

## [지형/배치 메커니즘]

- 메커니즘 이름: walk/build 역할과 화면 대비를 함께 선택
- 적용 이유/목적: 바닥·통로·발판·벽·방 경계를 시각적으로 식별시키고 실제 이동/건설 속성과 일치시킨다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 먼저 타일 속성에서 walkability, buildability, height를 확인한 다음 렌더된 타일의 시각 대비를 본다. 이름이나 RGB 요약값만으로 용도를 지정하지 않는다. 색 분석 JSON은 후보 비교 참고값이고, 기능 판정은 타일 속성과 실제 게임 이동으로 한다.
- 잘된 예시 및 실패하는 나쁜 예시: 시각적으로 다른 통로와 벽이 각각 이동 가능/불가 속성을 갖고 게임에서도 구분되면 성공이다. 어두운 색을 곧 막힌 타일로 취급하거나, 색상 유사도가 통행성 같음을 뜻한다고 보는 것은 실패다.

## [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 한 맵에는 하나의 tileset 테마를 사용한다. [지형을 다루는 방법 강좌](https://cafe.naver.com/edac/book5095400/66492)는 지형 종류는 함께 섞을 수 없으며 물·용암 같은 타일은 이동/건설 불가 속성을 가진다고 설명한다. 해당 타일셋의 실제 종류 속성을 확인한다.
- 유닛 길막/동선 보장 규칙: 통로/벽 색을 구분해도 최종 이동 경로는 Pathfinder Regions와 실제 게임으로 검사한다. 장식 doodad가 walkability를 바꾸는지도 확인한다.

출처: [스타 에디터 아카데미 지형 강좌](https://cafe.naver.com/edac/book5095400/66492), [오버레이 강좌](https://cafe.naver.com/edac/book5095361/76372). `data/tile-colors.json`은 렌더링 색 비교용이며 설계 통계/기능 표준이 아니다.
