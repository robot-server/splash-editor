# [지형/배치 메커니즘]

## 램프 후보를 고저 경계에 연결

- 메커니즘 이름: 타일셋 램프 doodad의 고저 전이 배치
- 적용 이유/목적: 본진·확장·중앙 사이에 실제 보행 가능한 고저 통로를 만든다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 램프는 ISOM 지형 종류가 아니라 램프 속성을 가진 여러 타일/미니타일을 덮어쓰는 DD2 doodad다. ISOM 고지 붓질만으로 통로를 내지 않는다. 현재 타일셋의 `data/ramps.json`에서 doodad ID, 폭·높이, 내려가는 방향을 고르고, 방향은 램프 doodad의 고지 덩이에서 저지로 내려가는 쪽과 맞춘다. 이 저장소의 `doodad place` 인자는 타일 중앙 좌표다. 사각 doodad를 왼쪽 위 `(x,y)`에 놓을 때 중심은 `(x + floor(w/2), y + floor(h/2))`이고, `scmap.place_doodad`가 이 변환을 한다. `scmap.place_ramp_checked`는 놓기 전에 `doodad fits`로 현재 지형의 `DoodadPlacibility` 표 호환성을 확인하고, 통과한 후보를 고저 경계 주변에 놓은 뒤 타일당 4×4 미니타일 격자에서 양쪽 끝의 연결을 검사한다. 배치 표가 없거나 맞지 않는 후보는 사용하지 않는다. 이 표 검사는 지형 조합만 확인하고 게임 내 통과를 증명하지 않는다. 후보 데이터의 `walks`도 별도 시험 지형에서 통했다는 뜻이다. 입구 폭, 착지 공간, 본진·확장까지의 전체 이동 경로도 따로 살핀다.
- 잘된 예시 및 실패하는 나쁜 예시: 타일셋과 방향이 맞는 doodad가 평탄한 고지·저지에 각각 겹치고, 에디터 배치 검사와 미니타일 연결 검사를 통과하며, 양쪽 착지부까지 지상군이 통과하면 성공이다. 고지 타일을 직사각형으로 덮어 ramp라 부르거나, 다른 방향/타일셋의 doodad를 놓거나, 램프 깃발·국소 BFS만으로 에디터 배치와 전체 경로까지 성립했다고 판단하는 것은 실패다.

# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 낮은 지형·높은 지형의 경계와 doodad의 방향/높이 단계가 맞아야 한다. SCMDraft `Height Transition`, `Pathfinder Regions`는 경사 위치와 보행 영역 단절을 찾는 진단 표시다. [오버레이 강좌](https://cafe.naver.com/edac/book5095361/76372).
- 유닛 길막/동선 보장 규칙: 실제 타일셋의 `walkable` 미니타일을 사용해 양쪽 평지에서 램프를 통과하는지 검사한다. 램프 양끝, 접근 초크, 착지 공간을 실제 게임에서도 확인한다. 코드의 국소 연결 검사를 전체 맵 통과 보장으로 간주하지 않는다.

생성기 근거: [램프 후보 측정 코드](../../.agents/skills/starcraft-map/scripts/measure_ramps.py), [타일셋별 후보 데이터](../../.agents/skills/starcraft-map/data/ramps.json), [배치·국소 경로 검사](../../.agents/skills/starcraft-map/scripts/scmap.py). `doodad place` 단독 명령은 배치 가능 표 검사를 하지 않으므로, 후보를 놓기 전에 `doodad fits`를 호출한다. 이 검사는 설치 데이터의 `DoodadPlacibility`와 현재 지형 타일 그룹을 비교한다.
