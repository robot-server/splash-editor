# [트리거/로직 패턴]

## 시민 토큰으로 유닛을 선택하고 교체하기

- 패턴 이름: 위치 기반 선택 토큰
- 구현하고자 하는 기능: 플레이어가 선택 위치로 시민 또는 다른 표시용 유닛을 가져오면 해당 유닛을 실제 보상 유닛으로 바꾼다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Bring(Current Player, 선택 토큰, 선택 위치, At least, 1)` → 선택 설명 `Display Text Message` → `Create Unit(Current Player, 보상 유닛, 수량, 결과 위치)` → `Remove Unit(Current Player, 선택 토큰)` → 필요하면 `Center View`, `Minimap Ping`, 효과음으로 결과 위치를 알린다. scmscx 원본에서 선택 위치별로 토큰을 감지하고, 설명·보상 생성·토큰 제거를 한 액션 묶음에 둔 사례를 확인했다.
- 예외 처리/버그 방지 로직: 토큰 제거가 같은 선택의 연속 발동을 막는다. 토큰을 남겨 선택을 반복시키는 방식이면 먼저 다른 위치로 `Move Unit` 하거나 쿨다운 상태를 기록한다. 보상 생성이 실패했을 때 토큰만 제거하지 않도록 생성 가능 조건 또는 환불/재시도 분기를 앞에 둔다.

## 비콘 구매와 실패 응답

- 패턴 이름: 조건부 차감 후 보상 생성
- 구현하고자 하는 기능: 비콘에 유닛을 가져온 플레이어가 충분한 자원을 가진 경우에만 정해진 비용을 지불하고 보상을 받는다.
- 조건(Condition) 및 액션(Action) 구조 체인: 성공 경로는 `Bring(Current Player, Men, 상점 위치, At least, 1)` + `Accumulate(Current Player, At least, 비용, Ore)` → `Set Resources(Current Player, Subtract, 비용, Ore)` → `Create Unit(Current Player, 보상, 수량, 보상 위치)` → 진입 유닛을 로비/출구로 `Move Unit`. 부족 자원 경로는 같은 `Bring` 조건 + `Accumulate(Current Player, At most, 비용-1, Ore)` → 부족 안내 → 진입 유닛 이동 또는 잠금 해제 대기.
- 예외 처리/버그 방지 로직: 성공과 부족 경로가 같은 트리거 주기에 모두 처리되지 않게 처리 상태를 두거나 진입 유닛을 즉시 이동한다. 비용을 빼기 전에 보상 생성이 가능한 공간과 플레이어 유닛 한도를 확인한다. 생성 실패 때는 비용을 돌려주고 실패 안내를 한다. 비콘 효과·비용은 진입 후 메시지만 쓰지 말고, 선택 전에 계속 보이는 표시에 같은 값을 적는다.

## 지역 대화·설명 트리거

- 패턴 이름: 위치 진입 대화
- 구현하고자 하는 기능: 플레이어가 특정 구역에 들어올 때 그 장소의 상황이나 다음 행동을 알려 준다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Bring(대상 플레이어, Any unit 또는 지정 유닛, 대화 위치, At least, 1)` → `Display Text Message(Always Display, 대사)` → 필요하면 대사 간 `Wait` 후 다음 메시지를 표시한다. scmscx 원본에서 순찰/이동 구간마다 다른 위치를 진입 조건으로 잡고 서사 대사를 연결하는 흐름을 확인했다.
- 예외 처리/버그 방지 로직: 지속 발동이 목적이 아니면 기본 일회성 트리거로 끝내고, 반복 안내가 필요하면 별도 스위치/데스값으로 재생 상태를 구분한다. 같은 플레이어 그룹에 여러 플레이어가 들어가면 대사가 여러 번 나오지 않는지 확인한다. `Wait`는 같은 플레이어의 다른 트리거 실행 순서에 영향을 주므로 서로 다른 반복 타이머를 한 플레이어의 웨이브 트리거에 섞지 않는다.

## 시간제 웨이브 생성과 종료 판정

- 패턴 이름: 단계 카운터가 있는 웨이브
- 구현하고자 하는 기능: 웨이브를 정해진 순서와 간격으로 내보내고, 모든 웨이브를 끝낸 뒤 생존 적이 없을 때 승리시킨다.
- 조건(Condition) 및 액션(Action) 구조 체인: `Deaths(제어 플레이어, 단계 카운터, Exactly, 현재 단계)` + `Countdown Timer(Exactly, 0)` + 필요하면 `Command(적 플레이어, Men, Exactly, 0)` → 지정 스폰 위치에 `Create Unit` → `Order(적 플레이어, Men, 스폰 위치, 목표 위치, attack)` → 단계 카운터 증가 → 타이머 재설정 → `Preserve Trigger`. 종료는 `Deaths(단계 카운터, At least, 마지막 단계)`와 `Command(적, Men, Exactly, 0)`를 함께 확인한 뒤 승리 처리한다.
- 예외 처리/버그 방지 로직: 각 웨이브에 유일한 단계 상태를 둔다. 적이 남아 있는 동안 다음 웨이브를 만들지 않을 설계라면 적 수 조건을 성공 조건과 같은 기준으로 쓴다. 여러 레인을 생성할 때는 생성 위치별 보행 가능 경로와 목표 도달 여부를 확인한다. 생성량과 생존 상한을 제한하고, 종료 판정이 새 웨이브 생성보다 먼저 승리시키지 않는지 순서를 확인한다.

## 설명 문구와 게임 규칙 연결

- 패턴 이름: 한 문장 설명과 실행 안내 브리핑 분리
- 구현하고자 하는 기능: 로비에서는 맵의 핵심 상황을 빠르게 고르게 하고, 시작 전에는 플레이 방법을 빠짐없이 익히게 한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 맵 설명에는 장르와 목표를 한 문장으로 쓴다. `Briefing`의 `Mission Objectives`에는 승리 조건을 요약하고 `Text Message`에는 시작 상태 → 조작 → 자원/구매 규칙 → 비콘별 효과·비용 → 승리/패배 → 협동 규칙 순으로 안내한다.
- 예외 처리/버그 방지 로직: 브리핑은 조건 분기 없는 직렬 안내이므로 맵 상태에 따라 달라지는 문구를 넣지 않는다. 브리핑의 효과·가격·목표 용어를 트리거의 실제 조건과 액션에 대조한다. 세계관 세부·공략·중복 요약은 맵 설명에 옮기지 않는다.

# [에디터 타일/배치 제약사항]

## 트리거 유닛 생성 공간과 보행 경로

- 지형 간 연결 규칙: 지상 유닛을 생성할 위치와 목적지를 같은 걷기 가능 영역으로 잇는다. 좁은 입구·절벽 고저차·걷기를 막는 두뎃이 위치 경계에 닿으면 생성 후 이동 명령이 있어도 목표로 가지 못한다.
- 유닛 길막/동선 보장 규칙: 고정 생성 위치에 기존 유닛·건물·장애물이 차지하는 칸을 포함해 스폰 포켓을 예약한다. 일괄 생성 수량이 한 포켓에 들어가는지, 남은 유닛 한도와 동시 생존량이 허용되는지 계산한다. 트리거 반복 전에 이전 생성물이 이동/제거되는지 확인한다. 생성 실패를 감지하면 비용·상태를 되돌리거나 대체 위치와 오류 피드백을 제공한다. `Create Unit`이 해당 위치에서 실패/겹침/이동 불가 중 어떤 결과를 내는지는 게임에서 확인한 조건만 검증 규칙으로 확정한다.
