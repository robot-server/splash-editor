# [트리거/로직 패턴]

## 유즈맵 시작 상태를 실제 플레이어 슬롯과 맞추기

- 패턴 이름: 사람 슬롯·컴퓨터 제어자·시작 조건을 명시
- 구현하고자 하는 기능: 플레이어가 올바른 종족·유닛·시야·트리거 상태로 게임을 시작한다.
- 조건(Condition) 및 액션(Action) 구조 체인: 슬롯과 Force 구성, 시작 유닛 배치, 중립 자원, 트리거 제어 플레이어를 각각 점검한다. 필요한 종족/유닛을 고정해야 하면 해당 설정이 게임 모드에서 적용되는지 실제 시작으로 확인한다.
- 예외 처리/버그 방지 로직 (예: 스위치 리셋, 트리거 순서 등): 아무도 맡지 않는 제어 플레이어에 트리거가 의존하지 않게 한다. 시작 위치와 사람 슬롯을 일치시키며, 유즈맵 특수 설정은 브리핑/로비 화면만으로 추정하지 말고 게임에서 검사한다. 자세한 트리거 소유자와 실행 순서는 [execution.md](../trigger/execution.md)를 참조한다.

# [지형/배치 메커니즘]

- 메커니즘 이름: 시작 동선과 기능 오브젝트 분리
- 적용 이유/목적: 진입 지점부터 조작·목표·보상 위치를 플레이어가 찾고 접근하게 한다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 시작 위치를 두고 각 상호작용 장소까지 이동 연결을 만들며, 상호작용 로케이션과 장식물을 겹치지 않게 구분한다. 게임에서 실제 시작 및 이동을 확인한다.
- 잘된 예시 및 실패하는 나쁜 예시: 시작하자마자 이동 경로와 사용 지점이 보이고 접근할 수 있으면 성공이다. 시야가 막혀 목표가 안 보이거나 지상 이동 경로가 끊긴 경우는 실패다.

# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 타일의 walk/build 속성과 시작 위치·목표 로케이션을 일치시킨다.
- 유닛 길막/동선 보장 규칙: Start Location 외에 트리거 상호작용 위치를 실제 유닛이 밟을 수 있는지 확인한다. 맵 설명과 시작 브리핑에는 서로 다른 양의 정보를 둔다: 맵 설명은 선택용 요약, 브리핑은 실행에 필요한 설명이다.
