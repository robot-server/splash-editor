# 유즈맵 장르별 공간 설계

## [지형/배치 메커니즘]

- 메커니즘 이름: 장르 규칙을 읽히게 하는 플레이 공간 구획
- 적용 이유/목적: 지형 형태는 플레이어가 어디에서 선택하고, 이동하고, 위험을 감수하는지를 전달해야 한다.
- 구체적 규칙 (타일 단위, 좌표 단위, 배치 각도, 언덕 연결 규칙 등): 퀴즈/선택형 공간은 선택 영역과 탈락·결과 영역을 시각적으로 구분하고 트리거 로케이션을 각 영역에 정렬한다. 탐험·전투형 공간은 분기 경로와 합류 지점, 스폰 위치와 목표 위치를 기능별로 정한다. 장르 이름만으로 사각형 또는 ISOM을 고정하지 않는다. 필요한 플레이 경로와 시야를 먼저 정한 뒤 타일 모드를 택한다.
- 잘된 예시 및 실패하는 나쁜 예시: 선택 패드와 해당 결과가 직접 대응하고 경계가 명확한 공간은 성공이다. 로케이션이 시각적 표식과 어긋나거나 스폰 적이 막힌 장식 지형 안에 놓이는 구성은 실패다.

# [에디터 타일/배치 제약사항]

- 지형 간 연결 규칙: 지상 이동을 플레이 규칙에 사용하는 경우 분기·합류·탈출 경로가 걷기 영역으로 이어져야 한다. 순간이동/생성 로케이션은 이동 연결과 혼동되지 않게 구별한다.
- 유닛 길막/동선 보장 규칙: 상호작용 로케이션에는 조건 검사 대상이 들어갈 수 있는 공간을 두고, 생성 로케이션에는 생성 후 목표로 이동할 수 있는 경로를 둔다. 실제 게임에서 트리거 조건과 유닛 이동을 확인한다.

장르 분류 집계는 공간 구획의 설계 근거가 아니다. 각 맵의 규칙과 트리거를 기준으로 구성한다.

## 추가 레시피의 공간 차이

코퍼스와 기능 문서에서 확인한 추가 플레이 루프의 공간 구성은
[genre-recipes.md](genre-recipes.md)에 정리했다.

- 숨바꼭질은 술래가 중앙 연결부를 오가고 숨는 쪽은 서로 다른 방 사이를
  이동한다. 방 경계는 눈에 보여야 하며 각 방과 중앙 홀은 보행으로 이어져야
  한다. 포획 판정이 구역 단위이면 Civ와 술래가 같은 로케이션 안에 들었는지
  정확히 검사한다.
- 마이크로 실기 시험은 시작/재도전 지점에서 각 도전 베이까지 이어지는 한
  경로를 둔다. 한 번에 한 적 무리만 풀고, 방마다 생성 가능한 footprint와
  Vulture 진입 공간을 남긴다.
- 방별 퍼즐은 허브에서 방으로 갈라지는 연결 그래프와 다시 모이는 출구를
  쓴다. Bring 위치와 표시 표식을 맞추고, Deaths 상태가 풀린 순서와 출구
  조건을 대조한다. 트리거가 열었다고 안내하는 게이트가 실제로 막히거나
  열리는지를 별도 확인한다.
- 사전 드래프트 협동 방어는 안전한 채용 홀과 여러 선택 상점을 전투 공간 앞에
  두고, 각 비콘에 보상 유닛 타입을 시각적으로 짝지어 보여 준다. 플레이어마다
  한 번의 선택/제한 시간 종료를 상태값으로 잠근 다음, 모든 선택이 끝날 때만
  적 웨이브를 시작한다. 상점의 Bring 위치·가격·결과 유닛과 웨이브 생성/주문
  로케이션을 각각 재검증한다.
