# 유즈맵 장르별 생성 레시피

기존 레시피끼리 같은 경기장 모양만 바꾸지 않는다. 먼저 이 표에서 플레이
루프가 맞는 시작점을 고르고, 단계 수·공간 연결·표식·실패 조건을 목적에
맞게 바꾼다. 생성기는 레시피의 뼈대이며, 최종 맵은 트리거 재독해·렌더·
게임 동작 검사까지 통과해야 한다.

## 코퍼스에서 관찰한 패턴

### 비대칭 숨바꼭질

- 코퍼스: [`yjkH6Bs5`](https://scmscx.com/map/yjkH6Bs5), TRIG 83개.
- 관찰: 사람 슬롯 1~6은 숨는 쪽이고 Player 7은 술래다. 준비 30초 뒤 생존
  제한시간을 건다. 준비가 끝나면 각 사람의 Civ를 플레이어별 방 위치로
  바꿔 Spider Mine 토큰으로 나타내고, Bring으로 술래가 있는 위치와 숨는
  플레이어의 토큰 위치를 대조한다. Deaths 카운터로 잡힌 상태를 기록하고,
  생존 토큰 수와 제한시간에 따라 승패를 처리한다. Set Alliance Status로
  사람·술래 관계도 바꾼다.
- 범위: 이 표본에서 확인한 구현 관찰이다. Room별 Bring 판정은 방 안 어디에
  있든 같은 방이면 잡힌 것으로 처리하는 영역 단위 판정이다. 모든 숨바꼭질
  맵이 이 변환·시간·팀 구조를 쓴다고 일반화하지 않는다.
- 생성 레시피: [숨바꼭질 생성기](../../.agents/skills/starcraft-map-usemap/scripts/make_hide_seek.py).
  단순한 민간인과 Deaths 상태를 써서 EUD 없이 역할과 포획 흐름을 구성한다.
  이는 코퍼스 구현을 그대로 옮긴 것이 아니라 대체 구현이다. 방 안 동시
  유닛·포획 판정, Alliance/Victory 공유, 타이머 종료는 실제 게임에서 확인한다.

### 단계형 마이크로 실기 시험

- 코퍼스: [`sG82kgDq`](https://scmscx.com/map/sG82kgDq),
  [`h34cchtd`](https://scmscx.com/map/h34cchtd). 두 자료는 같은 이름·유닛 구성·

  무리를 생성한다. Player 8 소유 Broodling 사망 수가 정확한 경계에 도달하면
  다음 적 종류를 생성하고, 플레이어 Vulture를 다시 주며, 광물을 더한다.
  Firebat·Zergling·Zealot 등 적 종류별 Deaths 경계가 단계 전이에 쓰인다.
- 생성 레시피: [벌처 실기 시험 생성기](../../.agents/skills/starcraft-map-usemap/scripts/make_micro_trial.py).
  이 레시피는 한 단계에 한 적 무리만 활동하게 하고 단계별 방에서 처치를
  완료해야 다음 무리와 보상이 나오도록 구성한다. 코퍼스의 시간 스폰·Deaths
  단계를 공간화한 권고이며, 실제 Create Unit 점유 실패와 적 Order 경로는
  별도로 게임에서 확인한다.

### 방탈출과 방 퍼즐

- 코퍼스: `_local-corpus/scmscx/use/_index.json`에는 시나리오/파일명에
  “방 탈출”이 들어가는 항목이 26개 있고 “탈출”이 들어가는 항목은 35개다.
  이것은 제목 빈도만 확인한 값이다.
- 직접 읽은 범위: 현재 CLI로 읽힌 방탈출 표본은 Set Memory와 Set Deaths를
  사용하며, 세부적인 비EUD 퍼즐 진행을 일반화할 만큼 근거가 충분하지 않다.
  읽지 못한 MPQ를 동작 증거로 취급하지 않는다.
- 기존 [일반 탈출 뼈대](../../.agents/skills/starcraft-map-usemap/scripts/make_usemap.py)는
  추격 적과 체크포인트가 있는 통과형 경로다. 방 탐색은 다른 공간·진행
  구조이므로 [방별 봉인 퍼즐 생성기](../../.agents/skills/starcraft-map-usemap/scripts/make_room_escape.py)를
  별도 레시피로 제공한다. 이 레시피는 Bring과 예약 Deaths 카운터로 세 방을
  순서대로 기록하고 출구 승리를 연다. 이 상태 흐름은 문서의 Bring·Deaths
  조립 원칙을 적용한 새 권고이며, 코퍼스 원본에서 직접 관찰한 체인과는
  구분한다.

### 사전 유닛 드래프트 협동 방어

- 코퍼스 집계: 트리거를 내보낼 수 있는 369개 중 15개(4.1%)에서, Custom 액션을 포함하지
  않는 단일 트리거에 `Bring(Current Player, 선택 유닛, 상점 위치, At least, 1)` +
  `Accumulate(Current Player, At least, 비용, ore)` + 상태 조건 + 선택 유닛 소비 +
  보상 `Create Unit` + 비용 차감이 함께 있는 맵을 검색한다. 15/369는 이 좁은
  성공 체인 필터와 일치한 map 수이며, 일반적인 상점 장르의 빈도가 아니다.
- 직접 읽은 범위: [대표 채용/구매 원본](https://scmscx.com/map/2BqjYVjT)의
  848개 트리거 중 읽을 수 있는 성공 체인에서 Marine/Ghost 선택 유닛, 자원 조건,
  Player 7 Beacon 상태 번호를 함께 검사한다. 선택 유닛을 치운 뒤 Jim Raynor나
  Sarah Kerrigan 영웅을 만들고, 비용을 차감하고, 성공 문구와 WAV를 재생한 뒤
  Preserve Trigger로 반복 판정을 이어 간다. 같은 원본에는 Beacon 번호별로
  난이도/진행 분기가 겹치므로 해당 맵 전체를 단일 shop-game 장르로 일반화하지 않는다.
- 체인 예: 성공 트리거는 Marine+30,000 ore 또는 Ghost+20,000 ore와 Player 7의
  Beacon 상태를 확인했다. 성공하면 선택 유닛을 상점 위치에서 치우고 맞는 영웅을
  다른 구역에 만든 뒤 자원을 차감한다. 새 레시피는 Player 7 Beacon 분기를 복제하지
  않고 각 사람의 선택 Deaths를 1회 구매 잠금으로 사용한다.
- 생성 레시피: [드래프트 협동 방어 생성기](../../.agents/skills/starcraft-map-usemap/scripts/make_loadout_gauntlet.py).
  이 레시피는 구매 루프를 전투 전 한 번짜리 팀 구성 단계로 사용하고, 모든 사람이
  고르거나 제한 시간이 끝나면 협동 웨이브를 연다. 프로필이 상점 비용·결과 유닛·
  마커·웨이브 수치·문구를 정한다. 선택 뒤 토큰을 상태 Deaths로 잠그고,
  상점 가격과 결과는 브리핑에 나열하며 Beacon 옆에 결과 유닛 타입을 함께 둔다.
  첫 적 무리는 중립 미리보기로 보이고 전투 시작 때 제거한 뒤 P7 유닛으로 새로
  생성한다. Remove+Create 순서와 spawn footprint의 생성 성공, 실제 Order 경로는
  게임에서 검사한다.

### 폭탄피하기

- 코퍼스: [`r8gbbp63`](https://scmscx.com/map/r8gbbp63)(64x64, 트리거 172개),
  [`yc766g76`](https://scmscx.com/map/yc766g76)(128x128, 트리거 98개). 둘 다
  시나리오 이름·설명에 "폭탄"과 "피하기"가 그대로 들어간다.
- 직접 읽은 범위: `splash-cli trigger show`로 두 맵의 트리거 전체를 다시 읽었다.
  `r8gbbp63`은 운영 플레이어(Player 8)가 `Switch` 조건으로 걸린 여러 트리거에서
  `Create Unit`으로 Dark Archon/Archon류를 격자·줄 모양의 로케이션에 놓고
  `Wait`(100~450ms)로 텔레그래프한 뒤 `Kill Unit At Location("All players", ...)`
  로 그 자리의 플레이어 유닛을 죽이며, 같은 로케이션에서 방금 만든 유닛도
  `Kill Unit At Location`으로 함께 지운다. `yc766g76`도 같은 생성→대기→
  로케이션 킬 체인을 쓰되 Wraith·Mutalisk 등으로 유닛 종류를 바꾸고,
  `Bring(사람, Men, "소생하기", At least, 1)`류 조합으로 부활을, 특정 로케이션
  진입 시 `Defeat()`를, 최종 로케이션 `Bring` 성공 시 `Victory()`를 건다.
  두 맵 모두 운영 플레이어와 사람 전원을 `Set Alliance Status`로 동맹 걸어
  폭탄 유닛의 일반 공격 판정이 아니라 트리거 킬만으로 즉사를 낸다.
- 범위: 이 두 표본에서 확인한 체인이다. 폭발 표시 유닛의 모양(스펠 이펙트
  대신 실제 유닛 스프라이트)과 패턴 배치(줄/격자)는 맵마다 다르고, 모든
  폭탄피하기 맵이 같은 부활·실패 조합을 쓴다고 일반화하지 않는다.
- 생성 레시피: [폭탄피하기 생성기](../../.agents/skills/starcraft-map-usemap/scripts/make_bomb_dodge.py).
  코퍼스의 "소생하기" 이중 Bring 조합을 그대로 옮기지 않고
  `scmap.part_respawn`으로 대체 구현한다 — 마지막으로 지난 체크포인트에서
  다시 살아나는 것은 같지만 판정 방식은 다르다. 스테이지 수·격자 크기·
  박자(어느 칸이 같이 터지는지, 텔레그래프 대기시간)는 전부 프로필이 정하고,
  코드는 좌표 범위와 코스가 실제로 걸을 수 있는 지형인지만 검사한다.
  코퍼스의 `t1`~`t25` 같은 폭탄 셀은 2x2타일로 작고 그 로케이션이 Create
  Unit·Kill Unit At Location에 그대로 같이 쓰인다 — 첫 구현은 이 대응을
  놓치고 스테이지 구간 전체를 cols x rows 로 나눠, 폭발 표시(유닛 한 기,
  점 하나)는 작은데 실제 즉사 판정 범위는 통로 절반을 차지하는 거대한
  기둥이 되는 결함이 있었다(렌더링으로 로케이션 크기를 직접 봐서 찾았다).
  코퍼스의 통로 폭도 실측하면 1~3칸을 넘지 않는 좁은 길이었는데, 첫
  구현은 그 제한이 없어 통로가 5칸까지 넓어졌다.
  지금은 `stages[i].cell`(타일 단위 셀 크기, 2x2 고정)을 프로필이 정해
  Create·Kill이 정확히 같은 작은 셀을 가리키게 했고, `stages[i].grid`의
  rows(통로 폭)를 1~3칸으로 스키마가 제한하며, 코스도 통짜 직선 한 줄
  대신 스테이지마다 위/아래 밴드를 번갈아 쓰는 지그재그로 바꿔 굽이를
  준다 — 코퍼스의 다갈래 미로를 그대로 재현한 것은 아니고, "직선 하나에
  셀이 거대하다"는 구체적 결함만 고친 대체 구현이다. 셀 사이 틈(`CELL_GAP`)과
  격자~게이트 여백(`CELL_PAD`)은 0으로 둬 순수하게 셀만으로 통로를
  구성하고, 이웃한 셀은 체크판처럼(`floor`/`pad` 몫을 번갈아) 타일을 갈라
  칠해 경계를 눈으로 읽게 한다. 폭탄 판정 순서도 코퍼스(Create → Wait →
  Kill, 폭탄이 잠깐 머문다)를 그대로 옮기지 않고 킬→생성→킬로 바꿨다 —
  Create Unit이 그 자리에 이미 있는 플레이어 유닛과 겹치면 옆 빈 칸으로
  밀려나 판정 위치가 어긋나므로, 생성 전에 그 자리 플레이어를 먼저 죽여
  비우고(이게 실제 즉사 판정이다) 폭탄을 만든 뒤 바로 지운다(화면에 머무는
  시간 없음). `Wait`는 판정 앞이 아니라 이 묶음이 끝난 뒤 다음 박자로
  넘어가는 간격이다. 폭발 표시 유닛이 실제로 격자 칸 중심에 설 수 있는지는
  `assert_create_targets`로 검사하지만, 박자 간격이 실제로 피할 만한
  난이도인지는 게임에서 확인해야 한다.
  안전지대(게이트·연결 통로)는 체크판(floor/pad)과 구별되는 세 번째
  타일을 쓴다. Palette는 (floor,pad)·(floor,rim)·(path,rim) 세 쌍만
  색 거리를 보장해 (pad,rim)이 가까울 수 있으므로, 시드 여러 개로
  Palette를 다시 뽑아 floor·pad 둘 다에서 가장 먼 rim/path 조합을
  고른다. 타일셋 자체가 저채도면(Ashworld 일부 시드에서 색 차 20 안팎)
  이 탐색도 한계가 있다 — 코퍼스 두 맵이 공교롭게도 둘 다 Space
  Platform을 쓰는데, 실측해 보니 그 타일셋이 이 방식으로 가장 뚜렷한
  대비(최대 44)를 낸다. 시작 지점은 체크포인트보다 훨씬 큰 방을 따로
  잡는다 — Start Location은 실제 건물을 안 놓아도 엔진이 종족 본진
  출입구가 있다고 가정해 검사하는 것으로 보이고, 통로가 좁으면(밴드
  두께 2타일 등) "건물 출입구가 막혔습니다"가 뜬다. 사람 수(+운영
  플레이어)만큼 2타일 간격 격자로 안 겹치게 배치할 수 있는 크기로
  방을 키운 뒤 실제 게임에서 그 메시지가 사라지는 것까지
  확인했다(2026-09-27).
  통로 폭을 좁게 잡으면 맵 바운딩 박스 대비 걷는 땅 비율이 낮아지는데,
  `verify_map.py`가 예전에 "못 걷는 땅 66% 초과 = 튕김"으로 걸던 것은
  85x48 Ashworld/Brood War 205, 못 걷는 땅 80% 조합을 실제 게임에서
  정상 진행되는 것으로 반증해(2026-09-27) 참고 정보로 낮췄다 — 자세한
  근거는 `tools/mapgen/verify_map.py`의 0a) 주석을 본다.

## 설명·브리핑·초상화 코퍼스 측정

로컬 유즈맵 코퍼스 인덱스 420개를 읽고 CLI로 CHK 설명과 미션 브리핑을
내보내 측정했다. Info를 읽을 수 있던 것은 369개, 실패는 51개였다. 설명이
있는 맵은 325개로 길이 중앙값 50자, 90백분위 119자, 최대 236자였고,
그중 244개(75%)가 80자 이하였다. 제목/맵 선택 화면 설명은 이처럼 짧은
컨셉 요약으로 두고, 조작 절차를 길게 싣지 않는다.

브리핑 액션을 읽을 수 있던 369개 중 315개는 비어 있지 않은 브리핑을
가졌다. 브리핑의 Text Message/Transmission은 중앙값 1개, 90백분위 3개,
평균 2.43개였다. Wait는 1,045개를 측정했고 지속시간은 중앙값 500ms,
90백분위 15,000ms였다. 이는 흔한 관측값이지 좋은 대기시간의 권고값은
아니다. 문장 하나씩 길게 멈추는 브리핑은 피하고, 필요한 조작·효과·비용·
실패 조건을 짧은 몇 문장으로 묶되 생성 프로필의 `briefing_hold_ms`로
표시 시간을 정한다.

비어 있지 않은 브리핑 315개 중 168개(53%)가 초상화를 사용했고, 서로 다른
초상화가 98종이었다. 자주 나온 Marine(44), Ghost(27), Civilian(27)만
기본값처럼 반복하지 말고 맵 주제에 맞는 유닛·영웅·건물을 프로필에서
정한다.

## 비콘 주변 결과 표식 측정

같은 코퍼스에서 읽을 수 있는 맵의 유닛 목록을 추출했다. 3,771개 Beacon류
배치 중 3,520개(93.3%)는 다른 유닛과 4타일 이내에 있었고, 3,725개(98.8%)는
8타일 이내였다. 가까운 이웃에는 다른 Beacon(1,095), Map Revealer(276),
Comsat Station(86), Civilian(85), Flag(65) 등이 있었다. 이 측정은 공간적
짝짓기를 보여 줄 뿐, 모든 가까운 오브젝트가 설명용이라는 뜻은 아니다.

새 상호작용에서는 시작 메시지에만 효과를 적지 않는다. 각 Beacon 바로
옆에 결과를 나타내는 관련 유닛/건물/표식을 둔다. 물체 이름을 커스텀할 때는
그 타입 전체에 적용될 수 있으므로, 같은 타입을 여러 다른 의미로 재사용하지
않는다. `functional-design.md`의 비콘 규칙을 따른다.

## 생성기 프로필

새 장르 레시피는 `.agents/skills/starcraft-map-usemap/scripts/recipe_config.py`의 JSON 프로필을 필수 입력으로
받는다. `.agents/skills/starcraft-map-usemap/scripts/recipe_profiles/`의 파일은 필드 모양 예시이며, 생성기는
그 경로를 기본값으로 열지 않는다. 문구·초상화·유닛·웨이브·타이머·보상·
초기 자원·업그레이드·기술은 맵마다 AI가 새로 적은 프로필에서만 온다.
예시 문장과 숫자를 그대로 맵 데이터로 쓰지 않는다. Python은 좌표·수량
범위와 템플릿 연결을 검증하며, 그 검사를 통과해도 실제 게임 동작은
별도로 확인한다. 생성기 출력은 최소 품질 골격이며 최종 맵이 아니다.
