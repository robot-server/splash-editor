# 유즈맵 — 사람을 붙잡는 구조

유즈맵에서 다투는 것은 재미다. 그래픽은 1998년에 멈춰 있으니 남는 것은
**되먹임 고리**뿐이다: 하고 → 바로 알려 주고 → 보상하고 → 다시 하고 싶게.

아래 숫자는 scmscx.com 에서 내려받기 수 기준으로 모은 **유즈맵 329장**을
전수로 뜯어 센 것이다. 디펜스·키우기·컨트롤·블러드·좀비·탈출·술래·랜덤·
땅따먹기·축구·퀴즈·바운드·헌터·스나이퍼·퍼즐·전쟁 등.

수치는 `data/corpus.json` 에 있고 `scripts/corpus.py` 로 읽는다.

## 0. 맵이 유즈맵답게 굴러가는가 — 먼저 이것부터

재미보다 앞선다. 아래를 빠뜨리면 **플레이하는 순간 망가진다.** 전부
실제로 플레이해 보고 지적받은 것이고, 실측 329장과 견주어 확인했다.

| 설정 | 실측 329장 | 빠뜨리면 |
| --- | --- | --- |
| 사람 슬롯 **종족을 못 박는다** | 테란 72%, 저그 14%, 프로토스 11%, **선택 가능 1%** | 스타팅 포인트에서 **본진 + 일꾼 네 기**가 나온다. 밀리처럼 시작해 버린다 |
| 1번 세력 **시작 위치 섞기 끈다** | 켠 맵은 **10%** 뿐 | 플레이어가 자리에 무작위 배정된다. P1 트리거가 엉뚱한 자리를 본다 |
| **Map Revealer 를 사람 전원에게** | 74% 가 씀, **주인 수 중앙값 5명**, 개수 중앙값 50 | 한 사람만 보이고 나머지는 깜깜하다 |
| 적 플레이어는 **컴퓨터** | — | "열림" 이면 아무도 안 앉을 때 유닛이 안 생긴다 |
| `Start Location` | **100%** | 게임이 시작되지 않는다 |

```python
scmap.setup_usemap_players(cli, humans=6, computers=[7, 8])  # 종족·세력까지
scmap.reveal_for_all(cli, humans=6)                          # 전원 시야
```

### 사거리를 재고 벽을 세운다

디펜스 경기장을 만들 때 **벽 두께가 사거리보다 두꺼우면 한 발도 못
쏜다.** 실제로 벽 4타일에 방어 유닛을 섬 가운데 놓아, 적까지 11타일이
되어 아무것도 못 때리는 맵을 만들었다.

| 유닛 | 사거리 | 지상 공격 |
| --- | --- | --- |
| 마린 | **4** (업그레이드 5) | ○ |
| 히드라리스크 | 4 (업그레이드 5) | ○ |
| **미사일 터렛** | 7 | **✗ 대공 전용** |
| 포톤 캐논 | 7 | ○ |
| 성큰 콜로니 | 7 | ○ |
| 시즈 탱크(시즈) | 12 | ○ |

- **미사일 터렛을 디펜스 타워로 쓰지 않는다.** 지상 웨이브를 못 때린다.
  지상까지 치는 것은 포톤 캐논·성큰·벙커다.
- 방어 유닛은 **섬 가운데가 아니라 가장자리**에 놓는다.

### 고도를 섞지 않는다

낮은 곳에서 높은 곳을 치면 **명중률이 53.125%** 다(빗나감 46.9%).
원거리만 해당하고 근접은 램프에서도 무조건 맞는다. 싸움터 바닥에
고도가 섞이면 같은 자리에서도 명중이 들쭉날쭉해진다.
`scmap.paint_floor_mixed` 는 고도를 하나로 묶는다.

### 누적 조건으로 보상을 주지 않는다

```
✗ Kill("Player 1", "Any unit", At least, 1);  →  Set Resources(Add, 25);
                                                 Preserve Trigger();
```

`Kill`·`Deaths` 는 **누적** 조건이다. `Preserve Trigger` 와 함께 쓰면
첫 킬 뒤로 **매 순회마다** 보상이 들어간다 (무한 돈). 죽은 수를
소비하는 것이 관용구다:

```
Trigger("Player 7"){          // 몬스터 주인
Conditions:
	Deaths("Player 7", "Zerg Zergling", At least, 1);
Actions:
	Set Deaths("Player 7", "Zerg Zergling", Subtract, 1);
	Set Resources("All players", Add, 20, ore);
	Preserve Trigger();
}
```

다만 이 방법은 **누가 잡았는지 못 가린다.** 경쟁 맵이라면 점수는
게임이 세 주는 `Leader Board Kills` 에 맡기고 돈은 시간 수입으로 준다.

### 필요한 만큼만 쓴다

**맵 크기와 쓰는 면적은 다른 이야기다.** 맵이 128x128 이라고 128x128 을
다 써야 하는 것은 아니다. 검은 여백이 남는 것은 정상이다.

거꾸로 **작게 만드는 것이 규칙인 것도 아니다.** 여섯 명이 각자 경기장을
쓰는 디펜스는 넓어야 하고, 두 발판 사이를 오가는 퀴즈는 좁아야 한다.
기준은 넓이가 아니라 **그 놀이에 필요한 만큼**이다.

그래서 순서가 이렇게 된다:

1. 놀이에 필요한 방 크기를 정한다 (동선·유닛 수·사거리로 정해진다)
2. 그만큼만 뚫고 가운데에 놓는다
3. 남는 자리는 검게 둔다

맵 크기에 맞춰 방을 늘리거나 나누지 않는다. 앞서 그렇게 해서 퀴즈
대기 구역이 세로 26칸이 됐고 12초 안에 못 가는 맵이 나왔다.

| 만든 맵 | 맵 크기 | 쓰는 테두리 | 왜 그만큼인가 |
| --- | --- | --- | --- |
| OX 퀴즈 | 64x64 | 35x13 | 좌우로 몇 칸이면 닿아야 한다 |
| 키우기 | 128x128 | 86x48 | 방 여섯 개를 잇는 데 그만큼 든다 |
| 사각 디펜스 | 128x128 | 120x79 | 경기장 여섯 개가 각각 38x38 이다 |

### 동선을 먼저 재고 방을 배치한다

제한 시간이 있는 맵은 **시간 안에 걸어갈 수 있는 거리**가 설계를 정한다.
OX 퀴즈를 처음에는 이렇게 만들었다가 12초 안에 못 가는 맵이 됐다:

```
✗  ┌──────────────────────┐   대기 구역이 위에 따로 (세로 26칸)
   └──┬────────────┬──────┘
   ┌──┴──┐      ┌──┴──┐       발판마다 좁은 통로를 따로
   │  O  │      │  X  │       → 위쪽에 선 사람은 서른 칸 넘게 걷는다
   └─────┘      └─────┘
```

고친 뒤 — **통로가 곧 대기 구역이다**:

```
✓  ┌────────┬──────┬────────┐
   │   O    │ 대기 │   X    │   가운데에 서 있다가 좌우로 몇 칸만
   └────────┴──────┴────────┘
```

대기 구역을 따로 둘 이유가 없었다. 고르는 두 곳 사이에 서 있게 하면
동선이 가장 짧고, 잘못 디뎠을 때 되돌아갈 것도 없다.

## 1. 실측 — 유즈맵 329장

### 규모

| | 중앙값 | 사분위 | 범위 |
| --- | --- | --- | --- |
| 유닛 | **677** | 274~1136 | 8 ~ 2476 |
| 트리거 | **237** | 124~421 | 3 ~ 4036 |
| 이름 붙인 로케이션 | **114** | 57~254 | 4 ~ 254 |
| 두뎃 항목 (DD2) | **0** | 0~42 | 0 ~ 541 |
| 스프라이트 (THG2) | 3 | 0~60 | 0 ~ 500 |
| **두뎃 타일 (MTXM)** | **868** | 398~3640 | 0 ~ 17013 |

**유닛이 677개다.** 밀리맵(134개)의 다섯 배다. 유즈맵을 만들면서 유닛을
수십 개만 놓았다면 그건 아직 빈 맵이다.

**로케이션을 꼭 255개 다 쓰지는 않는다.** 꽉 채운 맵은 329장 중 89장
(27%) 뿐이고 중앙값은 114개다. 다만 아껴 쓸 이유도 없다 — 트리거 판정의
거의 모든 것이 "어느 로케이션에 무엇이 있는가"로 굴러간다 (`Bring` 조건이
329장 중 320장, 97%).

**두뎃을 세는 자리가 둘이다. 앞서 틀렸다.**

여기 "두뎃 항목(DD2) 중앙값 0" 을 보고 "유즈맵은 두뎃을 안 쓴다" 고
적어 두었는데 **틀린 말이었다.** 에디터에서 놓은 두뎃은 저장할 때
지형(MTXM)으로 눌러 담기므로 **DD2 가 비어도 타일에는 남는다.**
타일 쪽(그룹 1024 이상)을 다시 세니:

| | 값 |
| --- | --- |
| 두뎃 타일을 쓴 맵 | 76장 중 **70장 = 92%** |
| 두뎃 타일 칸 수 | 중앙 **868칸** (사분위 398~3640) |
| 걷기 경계 두 칸 안에 놓인 것 | 중앙 **89%** (아무 칸이나면 54%) |

즉 유즈맵도 두뎃을 **많이** 쓰고, **방 테두리에 몰아서** 쓴다. 그래야
네모난 방이 방으로 읽힌다. 내가 만든 맵은 0칸이었다 — 그림으로 보고서야
알았다. `scmap.decorate_rim()` 이 이 일을 한다.

> **두뎃은 길을 막을 수 있다.** 바위를 방 가운데 놓으면 동선이 끊긴다.
> `decorate_rim` 은 놓은 뒤 미니타일 길찾기로 연결을 다시 재고, 깨지면
> 되돌려 성기게 다시 놓는다.

### 지형은 밀리와 딴판이다

| | 유즈 (중앙값) | 밀리 (중앙값) |
| --- | --- | --- |
| 쓰인 타일 그룹 | **150** | 504 |
| 서로 다른 타일 | **654** | 1995 |
| 되풀이(2칸 주기) | **15.7%** | 4.3% |

유즈맵 지형은 **되풀이가 밀리의 네 배**다. 벽으로 두른 네모를 격자로
늘어놓는 것이 표준이기 때문이다. 밀리맵에서 결함인 규칙성이 여기서는
정상이다. 다만 **타일 값 하나로 도배하지는 않는다** — 주기성 100%는
표본에 없다. `scmap.scatter_tile_variants()` 로 흩는다.

- **말해 준다.** `Display Text Message` 95%. 무슨 일이 일어났는지 글로

- **`Bring` 이 판정의 전부다.** 97%. 로케이션에 유닛이 몇 기 있는가로

- **점수를 보여 준다.** `Set Score` 72%, `Score` 조건 72%. 순위표는
  선택이 아니다.
- **화면을 옮겨 준다.** `Center View` 74%, `Minimap Ping` 42%. 중요한
  일이 일어난 곳으로 눈을 끌어 준다.
- **EUD 는 드물다.** `Memory` 7%, `Memory Masked` 2%. 없어도 재미있는
  맵을 만들 수 있다는 뜻이다.

| **Protoss Templar Archives** | **53%** | 업그레이드 파는 곳 |
| Zerg Hydralisk | 53% | 기본 병력 |
| **Zerg Evolution Chamber** | **51%** | 업그레이드 파는 곳 |
| Jim Raynor (Marine) | 49% | 영웅 — 강한 기본 유닛 |

**업그레이드 건물이 상위를 채운다.** Armory·Engineering Bay·Science
Facility·Forge·Templar Archives·Evolution Chamber 가 모두 50~65% 다.
유즈맵은 **업그레이드를 파는 구조**가 기본이라는 뜻이다. 건물을 놓고
플레이어에게 넘겨 주거나(`Give Units to Player`), 비콘을 밟으면
업그레이드를 올려 준다(`Set Upgrade Level`).

영웅 유닛(Jim Raynor, Kerrigan 등)도 자주 보인다. 능력치가 높고
**죽지 않게 만들기 쉬워** 주인공으로 쓰기 좋다.

## 2. 재미를 어디서 만드는가

위 숫자에서 읽히는 설계 원칙이다.

### 고리를 짧게, 그리고 끊기지 않게

`Preserve Trigger` 가 87개 맵에서 쓰이고, 트리거의 절반이 이걸 달고
있다. 유즈맵은 **한 번 하고 끝나는 트리거가 거의 없다.** 조건이 맞을
때마다 되풀이되는 고리가 맵을 굴린다.

고리 하나의 길이를 짧게 잡는다. 웨이브 하나, 뽑기 한 번, 라운드 하나가
**10~30초**면 "한 번 더"가 나온다. 3분짜리 고리는 지루하다.

### 한 일에는 반드시 반응을 준다

글(78) · 소리(50) · 미니맵 신호(28) · 화면 이동(44). 무슨 일이 일어났으면
**바로 알려 준다.** 조용히 지나가는 사건은 없었던 일과 같다.

```
Display Text Message("\x08+500원! \x07지금 3레벨");
Play WAV("sound\\Misc\\Button.wav", 300);
Minimap Ping(Location 5);
```

글자 색은 `\x01`~`\x1F` 로 넣는다. 인기 맵은 거의 다 색을 쓴다.

### 눈에 보이게 쌓이게 한다

순위표(64) · 점수(46). 지금 몇 등인지, 얼마나 모았는지가 **늘 화면에
떠 있어야** 다음 판을 한다.

```
Leader Board Points("\x1FP\x1Doints", Kills);
Leaderboard Computer Players(disabled);
```

### 보상은 유닛으로 준다

`Create Unit` 이 80개 맵 15982번. 자원(67개)보다 유닛이 먼저다. 숫자가
오르는 것보다 **화면에 뭔가 생기는 것**이 세다.

보상 계단을 만든다: 저글링 → 히드라 → 럴커 → 울트라. 같은 자원이라도
"더 센 것이 나왔다"가 보이면 다르다.

### 위기를 만들었다가 풀어 준다

시간 압박(24) · 적 압박(`Run AI Script`, 57). 웨이브가 몰려오고, 겨우
막고, 숨 돌리고, 다음 웨이브. 계속 편하면 재미가 없고 계속 힘들면
그만둔다.

디펜스에서 웨이브 난이도는 **계단이 아니라 톱니**로 올린다 — 5웨이브마다
한 번 쉬어 가는 웨이브를 넣으면 체감 난이도가 훨씬 낫다.

### 운을 섞는다

랜덤/운빨 장르가 따로 있을 만큼 크다. `Set Deaths` 로 만든 카운터를
`Switch` 와 섞으면 뽑기가 된다. 같은 실력이라도 결과가 달라지면 "한 번 더"가
나온다. 다만 **실력이 아무 소용 없으면** 금방 질린다 — 운은 양념이다.

### 쉬운 진입, 늦은 천장

퀴즈가 내려받기 1위(736)인 것이 말해 준다. 규칙이 한 줄로 설명되면
사람이 모인다. 첫 30초 안에 무엇을 하는지 알게 만든다:

```
Set Mission Objectives("...");        # F10 → J 로 볼 수 있다
Display Text Message("게임 설명은 임무목표(F10→J)를 보세요");
```

## 3. `Deaths` 를 변수로 쓰기

`Set Deaths` 가 30개 맵에서 **78059번** 쓰였다. 죽은 수를 세려는 게
아니라 **변수**로 쓰는 것이다.

StarCraft 트리거에는 변수가 없다. 대신 "플레이어 P 가 유닛 U 를 몇 번
죽였는가" 표가 플레이어 12명 x 유닛 228종 = 2736칸 있고, 쓰지 않는
칸을 마음대로 쓸 수 있다.

```
# 카운터 올리기
Set Deaths("Player 8", "Terran Vulture Spider Mine", Add, 1);

# 값 읽기
Deaths("Player 8", "Terran Vulture Spider Mine", Exactly, 10);
```

관례: 쓰지 않는 플레이어(보통 P8~P11)와 맵에 안 나오는 유닛을 골라
변수 자리로 쓴다. 어느 칸을 무엇에 쓰는지 **표를 만들어 두지 않으면**
금방 엉킨다.

`Switch` (256개) 는 참/거짓만 담는다. 수를 세야 하면 `Deaths`,
깃발이면 `Switch`.

## 4. 장르별 뼈대

`scripts/make_usemap.py --genre <장르>` 가 아래 뼈대를 깔아 준다.

| 장르 | 고리 | 핵심 트리거 |
| --- | --- | --- |
| `defense` | 웨이브 소환 → 막기 → 보상 → 다음 웨이브 | `Elapsed Time`/`Deaths` 카운터 + `Create Unit` + `Order` |
| `rpg` | 잡기 → 경험치 → 승급 | `Deaths` 로 경험치, `Bring` 으로 승급 자리 판정 |
| `control` | 붙기 → 이기면 점수 → 다음 판 | `Bring` 으로 남은 유닛 판정 + `Set Score` |
| `escape` | 피해서 나아가기 → 구역 통과 | `Bring` + `Move Location` |
| `tag` | 술래 정하기 → 잡기 → 술래 넘기기 | `Bring` + `Switch` |
| `quiz` | 문제 → 비콘으로 답 → 정오답 | `Bring` + `Display Text Message` |
| `luck` | 뽑기 → 결과 → 다시 | `Deaths` 카운터 + `Switch` 조합 |

자세한 트리거 조각은
[trigger-recipes.md](../trigger/recipes.md).

## 5. 흔한 실수

- **되먹임 없는 사건.** 뭔가 일어났는데 화면에 아무 말도 없으면 사람은
  모른다. `Display Text Message` 를 아끼지 않는다.
- **`Preserve Trigger` 빠뜨리기.** 한 번 돌고 죽는다. 되풀이할 트리거에는
  반드시 붙인다.
- **`Wait` 남용.** `Wait` 는 그 트리거 흐름을 멈춘다. 여러 트리거에서
  동시에 쓰면 "wait block" 이 걸려 엉뚱하게 굴러간다. 시간이 필요하면
  `Set Countdown Timer` 나 `Deaths` 카운터를 쓴다.
- **로케이션 아끼기.** 255개를 다 써도 된다.
- **너무 긴 첫 안내.** 30초 안에 첫 행동이 나와야 한다.

## 상점은 돈이 아니라 **물건 교환**이다

인기 유즈맵 134장에서 `Bring` 조건이 달린 트리거 **24,125개**를 전수로
세었다. "비콘에 서면 미네랄을 깎고 유닛을 준다" 는 내 기본 상점은
실측의 일부만 덮고 있었다.

| 값을 무엇으로 치르는가 | 비율 |
| --- | --- |
| 데려온 것을 **치운다** (`Remove Unit At Location`) | 25% |
| 데려온 것을 **밀어낸다** (`Move Unit`) | 21% |
| 데려온 것을 **죽인다** (`Kill Unit At Location`) | 16% |
| 조건에서 돈을 본다 (`Accumulate`) | 13% |
| 자원을 깎는다 (`Set Resources … Subtract`) | 7% |
| 주인을 바꾼다 (`Give Units to Player`) | 5% |
| 점수를 깎는다 | 2% |

| 무엇을 주는가 | 비율 |
| --- | --- |
| 유닛 (`Create Unit`) | 45% |
| 죽음 수 칸을 찍는다 — 곧 **상태** | 14% |
| 돈 | 9% |
| 스위치 | 8% |
| 능력치 (`Modify Unit *`) | 3% |

즉 유즈맵의 상점은 **토큰 교환기**다. 유닛 하나를 자리로 데려가면 그것이
사라지고 다른 것이 나온다. 돈은 곁가지다.

되풀이를 막는 방법도 같은 데서 나온다. `Preserve` 가 붙은 것 80% 중
**56%가 밀어내기·치우기로 잠근다.** 스위치로 잠그는 것은 1%, 자원
소비로 잠그는 것은 0% 다. **치우는 것이 곧 잠금**이기 때문이다.

- 물건 교환: `scmap.part_token_shop(...)`
- 돈으로 사는 것: `scmap.part_beacon_shop(...)` — 이쪽은 밀어내기를
  반드시 붙인다 (조건이 계속 참이라 매 프레임 사들인다)

> **21%는 눈에 보이는 잠금이 없다.** 인기 맵도 그렇다. "잠금이 없다" 를
> 무조건 결함으로 잡으면 성한 맵을 틀렸다고 한다 — 보상을 주는 트리거에만
> 세게 걸고 나머지는 참고로 둔다.
