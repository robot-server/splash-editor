# 사용자 허락이 필요한 맵 작업

이 문서는 EUD 가 아닌 일반 맵 편집·생성 중, 호환성이나 권리 보존에 영향이
큰 작업을 정리한다. EUD 를 쓰는 작업은 [EUD 안전 규칙](eud/limits.md)을
따른다. 아래 작업은 시작 전에 필요한 예외를 설명하고 사용자 허락을 받는다.

## 비표준 맵 크기

표준 가로·세로 크기는 각각 64, 96, 128, 192, 256 타일이다. 이 목록 밖의
크기는 어떤 게임 판본, 에디터, 배포 플랫폼에서 열고 저장할 수 있는지
달라질 수 있으므로 사용자 지정 크기와 실제 배포 대상을 먼저 확인한다.
표본 맵에서 사용됐다는 사실만으로 호환성을 보장하지 않는다.

물어볼 것: "왜 그 크기가 필요한가요? 어느 게임 판본과 플랫폼에서 사용할까요?"

## 미사용 유닛 번호와 비정상 상태

게임에서 쓰이지 않는 유닛 번호나 예상하지 않는 상태 조합(예: 지상 건물을
공중 상태로 두기)은 튕김·오작동·멀티플레이 desync 를 일으킬 수 있다.
필요성과 대상 게임 판본, 혼자 쓸 맵인지 배포할 맵인지 확인하고 진행한다.

## 맵 보호 풀기

```sh
splash-cli scenario unprotect map.scx -o out.scx
```

남이 만든 맵의 보호를 푸는 작업이다. 사용자가 그 맵에 대한 권리를 갖고
있는지 확인한다. 본인이 만든 맵을 복구하거나 학습 목적으로 분석하는 일은
가능하지만, 남의 맵을 자기 작품으로 내놓으려는 용도는 돕지 않는다.

## 규격 밖 구조를 다시 저장하기

부풀린 STR, 잘린 MTXM, 섹션 항목 수 초과처럼 일부러 만든 보호·서명 데이터는
다시 저장하면 정규화되어 깨질 수 있다. CLI 는 편집하지 않은 섹션 바이트를
보존하지만, 편집한 섹션은 다시 쓴다.

먼저 확인한다.

```sh
splash-cli roundtrip map.scx
```

`CHK 바이트 일치: 아니오`는 왕복 저장에서 CHK가 달라졌다는 뜻이지, 입력 맵이
규격 밖이라는 증거는 아니다. 달라진 섹션과 보호 데이터 보존 필요성을 설명하고,
원본을 보존한 채 진행할지 허락을 받는다.

## 허락을 묻는 방법

한 번에 묻는다. 하려는 작업, 필요한 이유, 호환성·보존 위험, 가능한 표준 대안을
짧게 말한다. 허락을 받지 못하면 표준 크기나 원본을 보존하는 대안을 사용한다.
