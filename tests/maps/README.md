# 테스트 맵 두는 곳

이 디렉터리에 `.scm` / `.scx` / `.chk` 파일을 넣으면 round-trip 테스트가
자동으로 찾아서 검증한다. 파일을 넣고 다시 돌리기만 하면 된다.

```sh
ctest --test-dir build --output-on-failure
```

## 왜 비어 있나

StarCraft 기본 맵과 배포 맵은 블리자드 또는 제작자의 저작물이라
이 저장소에 커밋하지 않는다. `.gitignore` 가 맵 확장자를 막아 둔 것도 그래서다.

맵이 하나도 없으면 테스트는 **건너뛰었다고 분명히 출력한다**. 합성 맵만으로
통과한 결과를 실제 맵 검증으로 착각하지 않기 위해서다.

## 어떤 맵을 넣으면 좋은가

M1 의 목표는 "열고 다시 저장해도 게임이 그대로 연다"이므로, 서로 다른
성격의 맵을 섞는 편이 좋다.

1. **작은 melee 맵** — 가장 단순한 경우. 예: 64x64 래더 맵
2. **문자열과 유닛이 많은 맵** — STR / UNIT 섹션이 큰 유즈맵
3. **보호되었거나 특이한 맵** — 섹션 순서가 비표준이거나, 알려지지 않은
   섹션이 섞여 있거나, 맵 보호가 걸린 것. "아는 섹션만 수정하고 나머지
   바이트는 보존한다"는 규칙이 실제로 지켜지는지 가장 잘 드러낸다.

리마스터 설치본이 있다면 `Maps/` 폴더에서 가져올 수 있다.

## 테스트가 확인하는 것

각 맵마다:

1. 열린다
2. 다시 저장된다
3. 저장본의 **CHK 바이트가 원본과 완전히 같다**
4. 저장본을 다시 열었을 때 메타데이터가 같다

맵 파일 전체가 아니라 그 안의 CHK 를 비교한다. MPQ 컨테이너는 해시 테이블
배치나 압축 결과가 달라질 수 있어, 내용이 같아도 바이트가 달라지기 때문이다.
보존해야 하는 것은 시나리오 데이터다.

## 게임에서 열리는지 확인

자동 테스트가 대신해 줄 수 없는 마지막 단계다. 저장본을 StarCraft 에서
직접 열어 봐야 한다.

```sh
./build/src/cli/splash-cli roundtrip <맵> /경로/Maps/재저장본.scx
```

출력된 파일을 게임에서 열어 정상 동작하면 통과다. 충돌이 나면 게임 쪽이
언제나 정답이다 — SCMDraft 2 나 우리 출력이 아니라.
