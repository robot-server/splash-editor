# StarCraft 밀리맵 제작

공통 절차·도구·판정 규칙은 [../starcraft-map/COMMON.md](../starcraft-map/COMMON.md)를 먼저 따른다. 이 문서는 밀리맵에서 다른 부분만 적는다.

## Plan (설계)

밀리맵은 크기·본진/앞마당/멀티 자원 자리·입구 종류·추가 지형 패치의 수/면적/종류·크리쳐 구성·전투 구역 건축 불가 지형을 이 맵마다 고른다. 여기서 정한 값을 Implement 단계에서 [make_melee.py](../starcraft-map/scripts/make_melee.py) 인자로 명시한다.

- 레시피 시작점은 [make_melee.py](../starcraft-map/scripts/make_melee.py)다. 먼저 `--help`와 생성 코드가 실제로 놓는 유닛·지형·로케이션·트리거를 읽고, 맵 목적에 맞게 바꾼다. 이름만 비슷한 옵션을 그대로 복사하지 않는다.
- 구조 지식을 적용할 때는 [docs/README.md](../../../docs/README.md)에서 관련 기능 문서로 이동한다. 밀리 지형·자원은 [지형 설계](../../../docs/melee/terrain.md), [기지와 자원 자리](../../../docs/melee/resource-sites.md), [자리 밸런스](../../../docs/melee/balance.md)를 참조한다. 램프는 [램프 진단](../../../docs/tileset/ramps.md), Bridge는 [Bridge 배치 한계](../../../docs/tileset/bridges.md)의 검증 범위를 확인한다.
- 밀리맵은 맵마다 AI가 크기·본진/앞마당/멀티 자원·앞마당 거리·바깥 멀티 수·입구·추가 지형 패치 수/면적/종류·크리쳐 종류와 수·전투 구역 건축 불가 지형을 고르고 `make_melee.py` 옵션으로 명시한다. CLI 기본값을 설계 의도로 복사하지 않는다. 맵의 가로와 세로는 사용자 허락 전까지 각각 64·96·128·192·256 중에서만 고른다. 그 밖의 크기는 [일반 승인 규칙](../../../docs/limits.md#비표준-맵-크기)을 먼저 따른다. 6인 이상은 128 타일 맵에서 자원 자리와 멀티가 겹치기 쉬우므로 192x192를 우선 검토한다. `--features`(0~64), `--feature-area`(8~384), 반복 `--feature-terrain`으로 AI가 고른 대칭 지형 덩이를 그리며 시작·자원 지대와 주요 진출로는 보전한다. 밀리 생성기의 Installation 제외는 설치본에서 본진·자원용 건축 가능 ISOM 바닥을 찾지 못한 측정에 따른다. `--main-entry auto`는 고지 경계를 찾아 타일셋에 맞는 후보를 `doodad fits`와 미니타일 연결로 검증하고, 최종 연결을 끊는 후보는 제거한 뒤 평지 입구로 복구한다. `--main-entry ramp`는 한 곳이라도 적합 램프를 못 놓으면 실패시킨다. `--main-entry bridge`는 현재 검증한 Jungle 타일셋의 2인 rot180 및 4인 rot90 템플릿에서만 사용하며, 양쪽 TILE/MTXM 패치와 두대드 정렬·최종 시작 연결을 검사한다. 다른 타일셋/대칭은 요청을 거절한다. AI가 정한 `--fight-zone` 안의 walkable·건축 불가 지형은 맵 대칭에 맞춰 복제하고, 구역 타일 중 새로 추가된 비율이 8% 미만이면 실패시킨다. 이 지형은 유닛 길을 막지 않으며 `--max-unbuildable-pct` 전체 타일 상한으로 기지·멀티를 보전한다(기본 30%, 최대 45%). 중립 크리쳐는 `--critters` 수를 0~플레이어 수로 제한하고 종류는 맵마다 AI가 고른다.
- 밀리 지형은 반복 무늬나 무작위 굴곡을 먼저 만들지 않는다. 시작지·자원·진입로·중앙 교전 구역의 관계를 실제 원본 맵에서 추출한 뒤 ISOM 형태를 구성한다. 같은 도형을 회전 복사해 모든 구역을 채우지 않는다.
- 제작 전에 아래 문서의 제약만 추가로 확인하고, 그 본문이나 유닛 목록을 맵 설명에 복사하지 않는다. [Disable 장식](../../../docs/tileset/disabled-units.md)은 Active 스프라이트로 길을 막지 않고, 메딕·시즈 탱크·골리앗에 Set Doodad State Disable을 쓰지 않는다. [두대드](../../../docs/tileset/doodads.md)은 타일셋이 허용하는 지형에만 두고 램프 입구와 자원면을 막지 않는다. [ISOM](../../../docs/tileset/isom.md)은 `(i+j)`가 짝수인 칸만 유효하고, 방향 있는 경계를 90도 타일 복사로 대칭하지 않는다. [밀리 생성 실패](../../../docs/melee/why-procedural-fails.md)는 면적이 맞는 방사형 윤곽을 전략 공간으로 두지 않고, 램프 조각 통행만으로 전체 경로를 보증하지 않는다.

## Implement (구현)

Plan에서 정한 값을 실제 `make_melee.py` 인자로 옮겨 맵을 만든다. 여기서부터는 Plan을 뒤집지 않는다.

- 램프 후보 표의 `walks`는 측정용 지형에서의 국소 미니타일 연결만 뜻한다. 배치 전 `doodad fits`로 타일셋 배치 표를 확인한다. 표가 없거나 후보 지형이 맞지 않으면 그 후보는 쓰지 않는다.
- 맵 이름은 한국어로 쓰되(기본 `ko`), 사용자가 언어를 따로 요청하면 그 언어로 바꾼다. API 구문, 유닛 타입 식별자는 원문을 유지한다.

## Test (확인 및 저장)

공통 Test 절차([../starcraft-map/COMMON.md](../starcraft-map/COMMON.md#test-확인-및-저장))에 더해 아래를 확인한다.

- 밀리 멀티는 자원 존재만 확인하지 않는다. 각 기지 건물 footprint, 테란 애드온 공간, 일꾼 채집 접근과 실제 게임 동작을 본다.
- 램프를 놓은 뒤에는 표만으로 끝내지 않고 국소 연결·착지부·게임 내 통과를 별도로 검증한다.
